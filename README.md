# SurvivorsDragonUi

A custom HUD for **Azeroth Survivors 0.87.0+**, using its official addon API. Install the addon alone; no companion process, client patch or special launcher is required.

See [Commands](#commands) for every addon command, including layout editing, reset, chat copying and combat-text modes.

## Install

1. Download `SurvivorsDragonUi.zip` from this repository's **Releases**.
2. On Windows or Linux, extract the ZIP. In the game, open **Options → AddOns** and click **Open AddOns Folder**, then place the extracted `SurvivorsDragonUi` folder inside it. You can also place that folder manually in `benilla-config/AddOns/` beside the game's executable.
3. The installed file should be at `benilla-config/AddOns/SurvivorsDragonUi/SurvivorsDragonUi.toc`.
4. In the browser version, use **Options → AddOns → install a .zip** instead.
5. Enable SurvivorsDragonUi and enter the world.

This targets Azeroth Survivors and its WoW 1.12.1 addon interface (`11200`). It is not a retail WoW addon. The native run HUD needs the game's 0.87.0+ API; unsupported clients retain their native run displays.

## HUD

- One locked action bar with seven buttons: native ability slots 1–6, followed by the permanent ability in native slot 12. Abilities cannot be dragged out or replaced by dragging, shift-clicking or placing a carried action. Normal ability use and the bar's `/sdui` layout controls remain available. No paging or gryphons.
- Ability buttons show centered, outlined DEFAULT-font cooldown numbers above their native swipes, keeping the existing artwork and layout. Text is red below one second; at one second or more, rounded seconds below five are yellow and five or more are white; longer waits use `m`, `h` or `d`. A total cooldown duration over 999 milliseconds qualifies. Remaining time rounds upward, except the final positive interval below 100 milliseconds displays `0`; ready abilities clear the label. Updates normally occur every 100 milliseconds and switch to every rendered frame during the final 200 milliseconds. The display follows native slots 1–6 and 12 and can be toggled with **Cooldown numbers** under `/sdui` → **HUD** (default off). Only the confirmed display preference is saved; cooldown data stays unsaved. See [cooldown implementation notes](docs/ABILITY-COOLDOWNS.md); in-game behavior remains unverified.
- An XP bar whose default placement is below the abilities, matching the action bar's default artwork width, without numbers or hover text.
- A gold bar whose default placement is directly below XP with three equal sections: kills, current gold and the next cache's gold cost. Kills use the enemy-hover sword cursor icon, current gold uses custom gold-coin artwork, and the cache cost uses the native loot-pouch cursor icon. Each section has a centered number.
- A blue run-progress pill with `RUN 05:42 / 16:00` centered above it using the client's Skurri font when available. Continuous river-like ripples flow rightward across the filled portion. At the native zone time limit, the full bar turns blood red with a steady warm glow and continuous stationary sparkles across its surface. The label then shows only elapsed time, such as `RUN 18:00`, continuing to count beyond the limit, and all timer skulls, checkmarks and marker glows hide. These cosmetic effects use UI time at up to 30 updates per second and continue while paused without advancing the run clock. The timer group defaults eight pixels higher on the screen and reads the native pause-aware clock and actual zone length. Before the limit, skull icons mark scheduled bosses: untriggered bosses keep the default skull; active bosses gain a pulsing red outline following its shape; killed bosses become 20% smaller at 70% opacity with a green checkmark. These appearances follow the official schedule's boss state. The outline gently brightens and moves inward and outward over 2.4 seconds without tinting or resizing the skull. Hiding markers at the limit preserves their native schedule states; the corresponding marker appearances return below the limit or in a new run. The user approved the effects using temporary fixed timer samples; live-run behavior, reload recovery and performance remain unverified.
- Separate red health pills for every live boss and engaged guardian, keyed by spawn id. With the matching native debuff API, every displayed encounter shows its own debuff icons, stack counts and known remaining times beneath its pill, enabled by default, including encounters you are not targeting.
- Player and target frames default to one uninterrupted health bar. The optional **Class resources** display integrates the player's native active resource below health inside the same frame.
- Player, target and target-of-target portraits attempt independent native animated unit models. The existing still portrait remains visible until the native model paint callback confirms a copy, and returns when that copy is unavailable. The current supported renderer uses a body view with rectangular bounds; face-only framing and true circular model clipping still require client support. Existing gold borders, unit-frame clicks and layout controls remain in use. See [animated portrait support](docs/ANIMATED-PORTRAITS.md) for client requirements and limits.
- Optional class resources default off. When enabled, the player frame includes its native active resource and attached point artwork. Warlock shards and Rogue points retain the native 20-unit encoding confirmed for the supplied v0.94.2 build; see [resource verification](docs/CLASS-RESOURCES.md#native-game-code-verification--2026-10-16) for the evidence and runtime limits.
- DEFAULT font throughout the UI except the run timer, square minimap, one backpack, and Character/Talents/Main Menu buttons, with the original gold WoW emblem for Main Menu. The talent button and N binding use the game's own talent window.
- Cast-bar and quest-watch displays are removed.
- The game's default weapon and jewelry build rows are hidden by default through the official native build-HUD API. The independent **Hide game build rows** toggle in `/sdui` → **HUD** can show them again, including alongside our equipped jewelry.
- Five equipped jewelry icons sit in gold circles attached above action buttons 2–6 by default, centered over each button and matching their spacing. The selected thin-bezel design adds only socket extensions at the original bar's upper edge, without the preview's extra lower curved line. The original bar texture, seven buttons and their positions are retained. The row shows the necklace, two rings and two trinkets, with native item tooltips and available circular cooldown swipes; empty sockets remain transparent. There is no jewelry panel, title or side ornament. Attached jewelry moves, scales and hides with **Action bar** through `/sdui`. Turn attachment off to keep the silver-gray circular outlines while moving and resizing **Equipped jewelry (detached)** independently. This equipment row is separate from the game's six-pickup run build and adds no abilities. See [equipped jewelry notes](docs/EQUIPPED-JEWELRY.md); in-game behavior remains unverified.
- Built-in scrolling combat text with optional damage icons, hidden by default, and independent animations that continue after kills, including with nameplates hidden. Icons use one shared resolver for every class: native spellbook and observed debuff metadata, the complete packaged custom talent icon catalog, learned native talents and spell-database metadata narrowed by the parsed damage school when names conflict. This also covers passive effects before any matching debuff has been observed. Unavailable or ambiguous icons retain the question-mark fallback; the packaged catalog supplies English names, while live native sources retain their localized names. Damage text smooths native plate-position changes during its animation. Normal hits are gray, stronger normal hits are yellow and critical hits are orange. Stronger means at least 20% above the average of that attack's last eight non-critical hits within 30 seconds, after three samples are available. Each ability/source and periodic tick type has its own temporary baseline; crits do not raise it.
- Matching SCT damage displays collapse to one unchanged number: three matching `100` hits show one `100`, with no addition or multiplier. Hits must have the same identified attack, resolved icon and original amount, arriving within 75 ms of the first hit. This fixed window spans updates and never extends when another hit joins. Different amounts and hits outside that window stay separate. Every original hit still participates in matching and damage-color history; combat logs and the native damage meter are unchanged.
- Compact nameplates with thin black borders, names above the health bars and raid markers. Health percentages and level indicators are hidden. The style stays active in every SCT mode and uses the existing V visibility control.
- Chat defaults to the bottom left with fully transparent backgrounds, fading messages, slide animation, mouse-wheel history reveal, a passive scroll indicator and a matching native input. Hovering or opening, closing or focusing the input does not reveal history or pause fading. New messages display normally, and fading pauses while wheel-scrolled back for reading until you return to the bottom. Chat tabs, the Combat Log tab and the Copy button are hidden. Level, stat-gain, self-loot and class talent-progress notices use compact source-style formatting; learned abilities and skill increases show `+Name`; NPC yells show a red name and colon followed by the message; other messages keep their original text. `/copy` opens raw session diagnostics, including hidden announcements and combat/addon events. The archive runs continuously and resets on reload; see [chat port notes](docs/CLEANERCHAT-PORT.md) for native-history limits.

Cache and **Guardian** waypoints add independent guidance HUDs and world-map pins. Each guide uses a horizontal floating label, 190 by 46 at its default size, with an upright 32-by-32 loot pouch for Cache or gold-dragon/skull medallion for Guardian. The DEFAULT 13 destination name floats above a left-aligned DEFAULT 15 distance beside the icon. A fine muted-gold stripe sits below the icon and text, which have transparent backgrounds. A direction arrow, visibly 20% larger than the selected design preview, rotates in place to the right. By default, Cache flanks the left side of the action-bar/XP stack and Guardian the right, centered on its combined artwork height with an eight-unit gap beyond the artwork edges. World-map artwork stays unchanged: caches use the tracked-waypoint diamond, and guardians use the rare-elite marker. Guardian pins include every occupied lair with a living guardian, asleep or fighting, and disappear when the lair becomes empty. Each guide selects a nearby destination automatically, keeps it until removed and allows another selection by clicking its map pin. Move and uniformly resize either guide separately with `/sdui`, preserving its 190:46 proportions; confirmed custom positions remain in use. Moving or resizing the action bar or XP does not resize the guides. Guardian distance and direction point to the fixed lair: a fighting guardian may have moved away. Each guide hides with its own unavailable waypoint. Separate **Cache guidance** and **Guardian guidance** controls in `/sdui` default on and independently hide each guide's HUD and world-map pins. Valid selections and geometry remain intact while hidden. These features add no minimap icons, 3D markers or gameplay persistence and need native snapshot replay after reload. See [waypoint notes](docs/CACHE-WAYPOINTS.md) for API requirements and limits; packaged-game behavior remains unverified.

Type **`/sdui`** to edit the layout, then **left-drag a frame's body** to move the player frame, target frame, boss/guardian health-bar group, run timer, action bar, XP bar, kills/gold/cache bar, micro menu, player buffs, minimap or chat. **Left-drag a corner icon** to resize that group. Each group moves and resizes independently: changing the action bar does not change XP or the tally. Editing shows outlines and corner icons, including for currently hidden HUD groups, without showing inactive targets or encounters. The main menu and Copy window support the same controls while open. Click the single **Confirm** button centered in the editor's footer to save all pending changes and lock the frames again. The editor and its footer stay above editing handles. Using `/sdui` again while editing keeps it open. Moving or resizing chat does not uncover faded messages; only the mouse wheel does that, and it still works during layout editing.

HUD groups resize by uniform scale, keeping their artwork proportions. Chat and Copy resize their actual width and height so text wraps and the viewport adjusts; their fonts keep their normal size. The action bar, XP and tally match at their default sizes, but can differ when resized independently.

The `/sdui` editor opens as one movable dialog with metallic artwork matching the HUD, organized into four tabs:

- **Layout** selects a registered frame with the arrow buttons or by clicking its editing outline. Enter center-relative **X/Y** coordinates, a **Scale (%)** for HUD groups, or **Width / Height** for Chat and Copy; **Hide frame** previews a per-group visibility preference.
- **HUD** groups Class-colored health, Class resources, Cooldown numbers, Boss debuffs, Cache guidance, Guardian guidance, Equipped jewelry, Hide game build rows and Attach jewelry to action bar as checkbox rows with descriptions.
- **Combat text** offers direct **Custom**, **Off** and **Game settings** choices for outgoing text, plus separate **Incoming/self text** and **Damage icons** checkboxes.
- **Run timer** shows a live label sample, a font dropdown, a size stepper, **None**, **Outline** and **Thick** outline choices, and **Shadow** and **Run text** checkboxes.

Left-drag the editor's background to move it; its width fits its controls and available labels. Its position and selected tab are session-only. Both `/sdui reset` and **Addon defaults** recenter it. **Confirm**, **Cancel** and **Addon defaults** share the footer, so every tab uses the same save, discard and reset actions. Artwork sources are recorded in the [editor artwork notice](third_party/SDUI-ARTWORK.md). The editor's appearance and integration remain unverified in the packaged game; no local validation or game startup was run.

The **Layout** tab starts with the player frame selected. X/Y use UI units from the screen center to the frame center: `(0, 0)` centers the frame, positive X moves right and positive Y moves up. Signed and fractional numbers, including decimal commas, are accepted. Scale is relative to the group's default and clamped to 40–300%; Chat and Copy retain their existing width/height limits and normal font size. **Apply position / size** previews the entered values while keeping the requested center fixed. **Confirm** also applies any pending valid numeric input before saving; invalid input keeps editing open with a message. Switching tabs preserves pending input. Selecting a different frame or pressing Escape in a numeric field restores the fields to the selected frame's current geometry.

**Hide frame** saves an optional `hidden` flag alongside that group's confirmed geometry in `SurvivorsDragonUiLayout`, without another SavedVariable. Hidden groups remain selectable; their editing outlines stay available where the owning module would normally show them. Unhiding a conditional target, encounter, waypoint or window leaves its normal visibility rules in control. This affects the selected layout group; waypoint HUD visibility here does not change the separate world-map pin controls. **Cancel** discards the complete editing session, including geometry, hidden flags, timer, display and combat-text previews. World leave, logout and reload also discard drafts. Both full resets remove saved hidden flags and restore each group's normal visibility rules. These community-contributed layout additions remain unverified in the packaged game.

The **Run timer** controls preview the top `RUN` label's font, size, outline and shadow. **Run text** shows or hides the entire `RUN elapsed / duration` label while keeping the progress pill and boss markers visible. Choose the game's `DEFAULT` face or its native Friz Quadrata, Arial Narrow, Morpheus and Skurri faces; no font download is needed. The initial timer settings are visible text in Skurri, size 14, normal outline and black shadow at offset `(1, -1)`, with DEFAULT as the fallback when a native font is unavailable. Existing confirmed font choices remain in use until changed or reset. **Addon defaults** immediately performs the same full reset as `/sdui reset`: it clears saved geometry and timer font/text choices, discards pending edits, restores all frame and timer font defaults with the label visible, and exits editing without requiring Confirm. The selected SCT mode stays unchanged. Other UI keeps DEFAULT.

**Cooldown numbers** in **HUD** defaults to **off**. Turn it on to show ability-button countdowns immediately while retaining the native cooldown swipes and action-bar styling. Confirm saves the choice in the existing display preferences; world leave/logout/reload discard unconfirmed changes. Missing or invalid saved choices and both full-reset controls use off. Previously confirmed choices remain in effect until changed or reset.

**Equipped jewelry** in **HUD** defaults to **on**. Turn it off to remove our five jewelry circles and their sockets and restore the original action-bar edge. It previews immediately, saves only with Confirm and rolls back with Cancel or world leave/logout/reload. Both full resets restore on. It does not change the game's native build rows.

**Hide game build rows** in **HUD** also defaults to **on**. Turn it off to show the game's original weapon and jewelry rows. It is independent of Equipped jewelry and uses the same live preview, Confirm-only saving, Cancel/discard and full-reset behavior. Unconfirmed native visibility is restored before reload/logout saving. The game API controls both native rows together.

**Attach jewelry to action bar** in **HUD** defaults to **on** and is available while Equipped jewelry is enabled. Off restores the original bar edge and displays the five jewelry circles with complete silver-gray outlines. Move, resize or hide **Equipped jewelry (detached)** independently in Layout; its confirmed geometry is retained when reattaching. Attachment previews immediately, saves only with Confirm, rolls back on Cancel or world leave/logout/reload, and returns to on with either full reset.

The **HUD** tab's **Boss debuffs** checkbox defaults to **on**; the **Combat text** tab's **Damage icons** checkbox defaults to **off**. Changes preview live, including on hits already animating. Each displayed boss or awake guardian reads its own official `AZS_GetDebuffs(spawnId)` list without requiring a target. Rectangular icons reuse the health pill’s metallic border textures, with native stack counts and tooltips built from the API's spell name, dispel type and timing. Known remaining times come directly from the native getter and pause with the run; permanent effects have no expiration countdown, and unknown timing stays unknown. These controls do not change the selected `/sct` mode or native outgoing text.

**Class-colored health** in **HUD** defaults to **off**. Enable it to tint the player health bar with the original WoW 1.12.1 class colors, with the requested blue Shaman override, while retaining the shaded health texture, metallic frame, centered value and damage-loss effect. It works with either the full-height health bar or Class resources enabled. The palette comes from the [original 1.12.1 UI color table](https://github.com/MOUZU/Blizzard-WoW-Interface/blob/master/1.12.1/FrameXML/Fonts.xml): Hunter `(0.67, 0.83, 0.45)`, Warlock `(0.58, 0.51, 0.79)`, Priest `(1, 1, 1)`, Paladin `(0.96, 0.55, 0.73)`, Mage `(0.41, 0.8, 0.94)`, Rogue `(1, 0.96, 0.41)`, Druid `(1, 0.49, 0.04)` and Warrior `(0.78, 0.61, 0.43)`. Shaman uses the requested blue `#0070DD` (RGB `0, 112, 221`, normalized as `0, 112 / 255, 221 / 255`) instead of the original vanilla pink. Missing or unknown class data falls back to the usual green. This player-only choice previews live, saves only with Confirm and uses the existing display discard/reset lifecycle. Appearance and behavior remain unverified in-game.

[Simulated class-color preview](docs/previews/player-class-health.png), composed from the shipped artwork with placeholder portraits and values; it is not an in-game screenshot.

**Class resources** in **HUD** defaults to **off**. Turn it on to divide the player's original bar opening into health above and the native active resource below, with its current value and native maximum range. Available combo points and the existing Warlock shard display sit beneath the frame with their original artwork. Health, the resource bar and these points move and resize together with the player frame through `/sdui`; target and target-of-target frames keep their health-only appearance. Turning the option off restores the full-height player health bar. This control uses the same live preview, Confirm, discard and reset behavior as the other display choices.

Survivors publishes Warlock shards and Rogue combo points through its active-power fields at 20 units per point; these meters retain that conversion, as recorded in [the native resource evidence](docs/CLASS-RESOURCES.md). Native target-dependent combo points are used only for other exposed mechanics, including energy-form Druids. The API does not expose an independent second mana/energy pool or a general third-resource getter.

In **Combat text**, **Custom**, **Off** and **Game settings** select outgoing combat text directly, while **Incoming/self text** separately controls the game's floating feedback for received damage and other self events. Both controls take effect immediately when clicked. Custom enables the addon's outgoing text and disables native outgoing damage numbers; Off disables both outgoing displays. Game settings selects the existing `default` mode and releases the preview's temporary outgoing suppression so native outgoing text follows the previous game preference. Incoming/self text changes only when you click its own checkbox. Click **Confirm** to keep the choices; selecting custom SCT leaves incoming/self text alone.

Only **Confirm** saves pending geometry and per-group visibility, timer font/text, display toggles and SCT mode to addon SavedVariables; releasing a drag or changing an editor control does not save those preferences. Confirmed locations, HUD scale, chat/Copy dimensions and per-group hidden flags persist across `/reload` and game sessions in `SurvivorsDragonUiLayout`; the confirmed timer font and label visibility are stored separately in `SurvivorsDragonUiRunFont`, and the display choices in `SurvivorsDragonUiDisplay`. The selected SCT mode uses `SurvivorsDragonUiSctMode`; incoming/self text uses the game's own preference. Unconfirmed edits are discarded on world leave, logout or `/reload`. SCT and incoming/self previews restore their prior choices unless you have since changed the affected native setting or issued an explicit `/sct` command. Rollback records exist only in memory. `/sdui reset` and **Addon defaults** discard every draft, clear saved geometry and hidden flags, timer font/text and display-toggle choices, exit editing and restore every registered group's defaults, including hidden frames, the visible run label, boss debuffs on, cooldown numbers off, damage icons off, class resources off and class-colored health off. Both resets keep the confirmed SCT mode and native incoming/self choice. Defaults stay defined in code; controls appear only during layout editing, without profiles or a separate settings window. Chat diagnostics remain session-only. A separate reload-only boss-schedule handoff is described below; other gameplay/native API state remains unsaved.

## Commands

All addon commands are listed below. Layout editing does not require holding SHIFT.

| Command        | Behavior                                                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/sdui`        | Open the Layout, HUD, Combat text and Run timer tabs to edit positions, sizes and visibility. Changes preview immediately; click **Confirm** in the editor footer to keep them and lock the frames. |
| `/sdui reset`  | Exit editing and restore layout, timer text and display defaults: visible run label, boss debuffs on, damage icons off, class resources off and class-colored health off.                           |
| `/copy`        | Open a snapshot of raw chat messages and events, including hidden messages; press **Ctrl+C** to copy the selected text.                                                                             |
| `/sct`         | Show the available combat-text modes and the currently selected mode.                                                                                                                               |
| `/sct on`      | Enable custom outgoing SCT and disable native outgoing damage text; preserve incoming/self text.                                                                                                    |
| `/sct off`     | Disable custom and native outgoing damage text; preserve incoming/self text.                                                                                                                        |
| `/sct default` | Disable custom SCT and leave the game's current combat-text settings unchanged.                                                                                                                     |
| `/fstack`      | Toggle a mouse-transparent frame inspector; `/fstack on` and `/fstack off` explicitly enable or disable it.                                                                                         |

`/fstack` inspects all Lua-exposed UI under the cursor, including the game's default frames, other addons, textures and text regions. It has no addon-ownership filter. `>` marks native mouse focus; `*` and a yellow outline identify the inspected element. The panel shows its name, parent, anchors, dimensions, effective owner scale, strata, frame level, draw layer and available texture/text metadata. Use `/fstack next` or `/fstack prev` to cycle every discovered overlap; the list pages around your selection. `/fstack focus` returns to following the mouse. The panel moves to the opposite side of the screen and leaves clicks and dragging available.

Scans run only while enabled, at most five times per second, including regions that extend beyond their owner's bounds. If global frame enumeration is unavailable, the inspector shows mouse focus, its parents and their regions; incomplete scans are labeled. Sorting by strata, frame level and draw layer does not reproduce exact native hit testing or draw order. UI drawn directly by the game renderer without Lua widget objects cannot be discovered by this addon. Inspection is session-only and closes on world leave, logout or reload; it saves no data. Packaged-client rendering remains unverified.

The game's **Enable Floating Combat Text** checkbox controls native incoming/self feedback independently of custom outgoing SCT. Changing it does not stop custom hits or switch SCT mode. Enabling **Show Target Damage** selects and saves `default` mode so native and custom outgoing numbers do not overlap. The addon observes game settings during startup, world entry and setting updates without rewriting them. `/sct on` and `/sct off` disable native outgoing damage text once when explicitly entered; neither changes incoming/self text. `/sct default` preserves the current native settings, so enable **Show Target Damage** separately to restore native outgoing numbers after `on` or `off`.

The normal **V** binding controls whether native nameplates are visible. While custom SCT is active, invisible native plates continue tracking enemies when V is off, so matched hits can follow them. Your V preference stays unchanged. Visible, invisible or recently retired plate positions are matched using names and health changes; unmatched or ambiguous hits appear at a shared fallback position. SCT mode changes clear active and queued custom hits immediately. The selected `on`, `off` or `default` mode is saved across runs, `/reload` and game sessions, subject to the native outgoing damage setting above. New installations and missing or invalid saved values use `default` mode and preserve the game's choices. Custom damage icons remain optional through `/sdui`. Combat logs and the damage meter are unaffected. Chat clicks and hyperlinks keep their native behavior.

## Client limitations

- Per-spawn boss and guardian debuffs require a matching game build that exposes the documented `AZS_GetDebuffs(id)` API. The addon feature-detects that getter; if it is unavailable, debuff icons stay hidden while encounter health bars remain available. It has no target-only `UnitDebuff` fallback and does not infer auras or timing from combat messages. Debuff data stays session-only, and recovery after `/reload` still depends on native snapshot replay. This integration has not been verified in the packaged game.
- `/reload` rebuilds the client's Lua state. The addon reconnects its clock, counters and encounters independently as native data arrives, and uses the official `AZS_RUN.fin` duration when once-per-run zone data is absent. Immediately before a hooked native `ReloadUI` call, it saves a complete boss schedule in `SurvivorsDragonUiBossSchedule` for one initialization, then clears the saved value. Markers can reuse it once current native run data passes continuity checks; a complete live schedule always takes priority. Changed boss counters, a new zone/run or normal world leave/logout discard the handoff. The API has no documented run identifier, so this is best-effort reload continuity, not a general game-session cache. Full reliable recovery, including unchanged encounters or a missing/rejected schedule handoff, still requires client snapshot replay. The addon cannot request that through the documented API, and this reload behavior has not been verified in the packaged game. See [reload notes](docs/RELOAD-API-NOTES.md).
- Nameplate collision stacking is controlled by the client. This build exposes no overlap switch to addons.
- A newly allocated native nameplate can briefly appear before the addon skins or masks it, including with V off while custom SCT keeps native tracking active. The current client source creates new plates after Lua's update callbacks and before drawing; the addon has no supported first-creation callback before that draw. Eliminating that first-frame gap requires client support. Known pooled plates already have immediate show/health hooks.
- Custom SCT uses native plate coordinates, including the client's collision displacement. With custom SCT on and V off, keeping invisible tracking active can also leave native overhead enemy names suppressed. The tracking integration has not been verified in the packaged game; see [API notes](docs/API-NOTES.md).
- The original 1.12 combat log identifies enemies by name rather than destination GUID. Same-name hits can have ambiguous positions; the addon shows those hits at a shared or fallback position.

The original official API reference is included in [docs/AzerothSurvivors-Addon-API.md](docs/AzerothSurvivors-Addon-API.md). The owner's updated reference supplied on 2026-10-15, including per-spawn debuffs, is preserved verbatim in [docs/AzerothSurvivors-Addon-API-2026-10-15.txt](docs/AzerothSurvivors-Addon-API-2026-10-15.txt).

## Automated releases

Each push to `main` that changes the installable payload builds one `SurvivorsDragonUi.zip` from that push's final commit. The payload is listed in `packaging/runtime-files.json`: the TOC, its loaded Lua files and the textures used at runtime. The ZIP contains only those files inside the installable `SurvivorsDragonUi/` folder. Repository documentation, tooling, workflows, unused source/artwork and standalone license/attribution files stay on GitHub. Required third-party license text remains in the packaged Lua source comments.

Release eligibility uses the same manifest as packaging, including removed files and changes to payload membership. PRs that change the shipped ZIP payload must increase the TOC version. Documentation/tooling-only PRs leave the version unchanged and do not publish a release. Files outside the payload and manifest formatting alone do not trigger packaging; publication is skipped when no packaged content changed.

Releases use the final commit's SHA as their tag. Re-running the same build replaces its ZIP without creating another release. Publication is serialized, and an older rerun cannot replace a newer Latest release. The stable [latest ZIP download](https://github.com/migwynkriid13/SurvivorsDragonUi/releases/latest/download/SurvivorsDragonUi.zip) points to the newest published build. A manual workflow run on `main` can also package the current commit.

Packaging and publishing do not run the addon, launch the game, or perform addon validation. A published release is a packaged snapshot, not proof of in-game validation.

To package locally with Python 3:

```sh
python3 scripts/package.py dist/SurvivorsDragonUi.zip
```

## Pull request checks

PRs that change the shipped ZIP payload must set `## Version` in `SurvivorsDragonUi.toc` strictly higher than the latest target `main` version, keeping the `major.minor.patch-survivors` format and `-survivors` suffix. Default to one patch increment, for example `3.2.2-survivors` to `3.2.3-survivors`. Bump once per qualifying PR, not on every commit or push. If another merge brings `main` to the same or a higher version, update the PR version before merging. Documentation/tooling-only PRs leave the version unchanged. PR-introduced payload impact uses the shared release comparison of the PR merge-base and PR-head `packaging/runtime-files.json` manifests, including removals and membership changes.

An automated metadata guard uses that shared payload comparison and requires a version increase when shipped content changes, comparing the pinned PR head with the target branch's current version when CI runs. The protected `main` branch requires the GitHub Actions check **Formatting and local dead code** to pass and the PR branch to be up to date before merging, including for administrators. Preserve this protection unless the user explicitly authorizes changing it. CI never bumps or commits the version automatically.

Every push to a pull request runs all source-quality checks across the complete tracked codebase. Prettier checks owned Markdown, JSON and YAML; StyLua checks all Lua formatting; Luacheck reports unused local variables and assignments, unreachable code and single-iteration loops. These checks never load the addon or start the game.

The version guard and all three source-quality checks finish before CI enforces the result. One combined job summary and downloadable artifact contain the version result, every tool's findings and suggested formatting patches; CI does not commit changes automatically. The supplied API reference and upstream WidgetStatusBar attribution stay verbatim. Lua formatting uses the nearest supported grammar, Lua 5.1; it does not establish 1.12 runtime compatibility. Dead-code analysis excludes dynamic WoW/DFRL globals and unused callback arguments, and cannot prove that globally registered callbacks or assets are unused.
