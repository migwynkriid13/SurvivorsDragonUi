# Ability cooldown numbers

The seven action buttons retain their existing artwork, spacing, native cooldown swipes, click handlers, locked slots and shared layout scaling. An anonymous child frame on each button draws a centered DEFAULT-font countdown above its swipe, with a 14-pixel maximum, outline and black shadow. These labels inherit their button's scale, alpha and visibility.

The appearance is inspired by [Turtle Dragonflight's cooldown-number module](https://github.com/DustinChecketts/Turtle-Dragonflight/blob/b2c62e9095e1c859bff0209db09f4ff5b9884f5a/mods/cooldown-numbers.lua) and [time formatter](https://github.com/DustinChecketts/Turtle-Dragonflight/blob/b2c62e9095e1c859bff0209db09f4ff5b9884f5a/helpers.lua#L266-L282), by TheLinuxITGuy with Shagu's cooldown-number styling. This addon uses the user-selected local thresholds: red below one actual second; otherwise yellow for rounded-up seconds below five and white for rounded-up seconds of five or more. Remaining time uses rounded-up seconds or abbreviated minutes, hours and days. Red takes precedence below one actual second, including the final `0`. At one second or more, colors follow the rounded-up seconds: displayed `2` through `4` are yellow and displayed `5` or more is white. Exactly one second is yellow; exactly four seconds is yellow, while just above four seconds displays a white `5`. There is no minimum total-duration cutoff: any positive native cooldown duration can show a number while positive time remains. A positive remaining time strictly below 100 milliseconds displays `0`; exactly 100 milliseconds still displays `1`, and zero or expired time hides the label. Both 0.7-second and 1.7-second cooldowns qualify; global cooldowns are not separately suppressed.

This is an independent implementation inside `modules/bars/bars.lua`, with no imported upstream code, artwork, modules or dependencies. One updater reads `GetActionCooldown(ActionButton_GetPagedID(button))` normally every 0.1 seconds, with immediate refreshes for native cooldown and slot-change events. If any displayed cooldown has at most 0.2 positive seconds remaining, it switches to every rendered frame until no qualifying cooldown is in that final window. This avoids having the normal 100-millisecond cadence skip the brief zero display. Only a sampling-mode boolean is retained; every refresh still rereads native timing. No artificial zero hold or independent completion clock is added. If the client renders no frame in that interval, the addon cannot display it retroactively. The seventh displayed button continues reading native slot 12. The same native getter supplies the stock [1.12.1 action-button cooldown swipe](https://github.com/MOUZU/Blizzard-WoW-Interface/blob/master/1.12.1/FrameXML/ActionButton.lua#L279-L282).

Each refresh rereads native start, duration and enabled state instead of retaining its own cooldown countdown. Missing, disabled, expired or unusable timing and empty/hidden buttons hide their labels. World leave/logout clear the numbers; world entry rereads current native values. The code does not modify native cooldowns, hook the global cooldown renderer, touch encounter debuff timers or persist gameplay state.

Disabled, hidden and out-of-world states detach the existing callback. Native
events, Show and display changes rearm it through the same controller. Enabled
readiness retries and final-window sampling retain their original cadence.

Each of the seven overlays caches only its latest rounded caption value, unit and language. Repeated samples in the same display bucket reuse that string instead of localizing and joining it again. Native timing reads, the final-window cadence and immediate event refreshes continue unchanged. Every refresh still compares actual text, color and visibility, so native resets and failed text writes remain retryable. Disable, bar hiding and world cleanup clear the caption caches with the labels. The cache contains no start, duration or remaining-time history and adds no frame, drawing region, asset or saved data.

The **Cooldown numbers** checkbox in `/sdui` → **HUD** defaults on. It uses the existing `SurvivorsDragonUiDisplay` preference table, storing only the normalized boolean `cooldownNumbers`; missing or invalid values use on. Previously confirmed boolean choices remain in effect until changed or reset. Clicking previews immediately and turning it off clears the labels, resets the final-window sampling flag and skips periodic native cooldown reads. Confirm alone saves; world leave/logout/reload discard drafts, and `/sdui reset` or **Addon defaults** restore on through the shared display reset. It uses the existing shared editor and footer. No commands, assets or separate SavedVariables are added.

The caption-cache follow-up uses source review and pinned local formatting. CI-only mocks exercise repeated caption reuse while all seven native reads continue, unit/language changes, actual widget resets, failed text writes, cleanup and final-window sampling. No local tests, standalone validation or addon/game execution were run. These source-level changes and authored mocks do not establish measured CPU time, stutter recovery, native-swipe rendering or in-game compatibility.
