# Integrated chat port

The supplied CleanerChat 2.44 source targets Interface 30300. SurvivorsDragonUi adapts its glass-style presentation for an Interface 11200 chat window, including fading, animation and styled controls. Here, "prettify" means formatting the messages themselves. Only the requested level, native stat-gain, self-loot, class talent-progress, ability-learning/skill-increase and NPC-yell messages are formatted; other incoming messages retain their original text. No separate chat addon is required. Source attribution and the supplied license metadata are retained in `third_party/CleanerChat-NOTICE.txt`.

## Presentation and incoming text

The chat window defaults to 520 by 340 pixels, with a default bottom-left position, 20 pixels from the left edge and 40 pixels above the bottom edge to keep the input and scroll indicator onscreen. It uses the game's DEFAULT font at 12 pixels with an outline, fully transparent backgrounds (opacity 0) and a stripped native input skin. `/sdui` enters layout editing: left-drag its body to move it or a corner icon to change its actual dimensions, updating native message wrapping without scaling fonts. The centered Confirm button saves the pending geometry and locks it again. All native and custom chat tabs, the Combat Log tab and the Copy button stay hidden. The message pane, input and scroll indicator have no background textures, and the copy dialog has a transparent fill. New activity slides the message pane into position over 0.35 seconds. Native message lines remain visible for 14 seconds before a 0.6-second fade. Only the mouse wheel over the chat area reveals retained faded messages; hovering, layout editing/moving/resizing and input show/hide/focus do not reveal history or pause fading. New messages still display normally. Revealing old, faded history fades the pane in over 0.6 seconds, without restarting that intro on each wheel notch. Fading stays paused while wheel-scrolled back for reading and resumes when the wheel returns to the bottom. The passive scroll indicator shows `Scroll down for latest messages` or unread status while viewing history; it has no clickable snap-to-bottom action. `/copy` opens the Copy dialog.

The primary `ChatFrame1` receives regular chat and game notices while preserving native channel membership and routing. Combat-log groups for attacks, damage, healing, auras and deaths are removed from the visible regular chat, including subscriptions saved by the earlier all-groups setup. XP, honor, reputation, tradeskill and item-enchantment notices remain in regular chat. The separate native Combat Log frame keeps its subscriptions and unmodified text, with its tab hidden. The diagnostic archive captures combat events independently, without adding them to regular chat. Presentation animation does not authorize additional message-formatting changes.

`modules/chat/prettify.lua` applies only the explicitly requested formats, using the supplied source's `Core/API/Output.lua`, `Core/Common/Colors.lua`, `Experience.lua` and `Loot.lua`:

- The level and its immediately following native stat notice are combined into one chat message: `Level 16: +3% Damage, +9 HP, +0.08 HP/sec`. The level stays amber, adapting `levelup_ding`, with green gain signs/labels and white numeric values from `levelup_stat`/`levelup_hp`. Percentages and decimal values are retained rather than rounded. Each native frame briefly holds a recognized level announcement for up to 0.25 seconds; a matching adjacent stat notice is merged, while an intervening message or elapsed delay flushes the standalone level first. Levels without gains remain visible. Native metadata/order are retained. The diagnostic archive captures the original inputs before this coalescing; an available native-history snapshot can also contain the resulting displayed line.
- Self-loot becomes a green `+` directly followed by the item name, matching `item_single`, with no visible space after the sign. Anchored self-loot is recognized on loot/system channels and in direct Lua writes. Colored/uncolored hyperlinks, colored/uncolored bracketed plain names and colored announcement prefixes are supported. The `You receive loot:` prefix and visible name brackets are removed; complete link data when supplied and item color are preserved. Explicit native `(already collected)` status hides the self-loot line from regular chat using the shared parser's `collection == "collected"` result, matching the loot cards. New or unstated collection status keeps the compact message; `New in your collection!` retains its supplied wording and color, defaulting to green when uncolored. Raw diagnostics still capture the original input. Unknown suffixes leave the entire message unchanged.
- Class talent-experience notices adapt the original named-XP and stat-gain styles: `+420 Talent XP: Rogues, +1 Talent Point (Spend in armory)`. Class labels, XP and point counts are captured from each incoming message, including compound/plural class names, `earn`/`earns`, singular/plural point awards and XP-only notices. No specific class or amount is hardcoded. The armory prompt appears only when supplied, and unknown suffixes remain unchanged. System, native level-up and XP event contexts are supported; ordinary combat XP text is not reformatted by this rule.
- Learned or trained abilities, spells and passive effects show a green `+` directly followed by the incoming name, such as `+Rupture (Rank 1)` or `+Adrenaline Rush`. Native 1.12 training uses the learned-message formats, retaining any rank text or hyperlink within the name. Gained skills and skill increases likewise show only `+Skill name`, omitting the increase counter. Native localized GlobalStrings and anchored English fallbacks recognize system/skill messages and direct Lua writes. Names are never hardcoded; recipes and unlearning notices retain their original text. This explicitly replaces the source's suppression of spell-learning notices.

Every prettified message uses `+` directly against the following value or item, with no visible space after the sign. This rule also applies to future requested formats; it does not change incoming text that is otherwise preserved unchanged.

The requested encounter announcements are hidden from native chat rendering after raw capture: `<mob> approaches!`, `<mob> claims its lair once more.`, `<mob> enters the battlefield!`, `<mob> refuses to fall!`, `<encounter> — survive the onslaught!`, `Swarm surrounds you!`, `A stampede charges through!`, `A wall of foes closes in!`, `A pack hunts you!`, and `<guardian> is slain! Its lair yields treasure and its strength, and the other guardians grow stronger.` Nameless lair/battlefield/refuses-to-fall/onslaught/guardian-slain forms are also hidden; the onslaught separator accepts an em dash, en dash or hyphen. Matching uses complete announcement wording after removing color markup, with any mob, encounter or guardian name; no names are hardcoded. The guardian rule requires the complete lair/strength announcement. Stampede, wall-of-foes and pack notices match only their complete native wording in all fourteen languages; their custom banner delivery remains unchanged. The rule applies to system messages, monster and raid-boss emotes, and direct Lua writes, leaving player conversations, NPC yells and error reports intact. Hidden lines remain in Copy's diagnostic archive but do not interrupt a pending level/stat pair or create unread/slide activity.

NPC yells now follow the requested `NPC name: message` form, with a red name and colon and no `yells` word. The name and dialogue come from the native monster-yell event, so the rule works for any NPC and localized native prefixes. Player yells and unknown messages remain unchanged. This is an explicit extension beyond the source, which excludes `MONSTER_YELL` from general parsing. The formatter runs before the original native `AddMessage`, with raw-text fallback if formatting fails. Native event context includes `PLAYER_LEVEL_UP`; direct Lua writes can match the same anchored progress/loot notice patterns without an event. NPC dialogue requires monster-yell event identity to avoid confusing players with NPCs. Copy captures raw events and inputs independently of their displayed formatting. A direct native write that bypasses Lua remains visible but may bypass formatting, too.

Native chat frames retain scrolling, their own history and game hyperlinks. The shared vanilla `ChatFrameEditBox` keeps slash commands, whisper/reply routing and sent-message history. Outside layout editing, native click and hyperlink handling keeps item viewing, modifier-click and player-link actions. The addon does not intercept right-clicks to open Copy or turn ordinary URLs into custom hyperlinks.

Rendering stays with the native frames, preserving their output even when a write does not pass through the Lua `AddMessage` hook. Message visibility is independent of the copy/animation hook. The original blank custom-row display was not diagnosed in-game; this implementation also retries setup if the first native frame is not ready at addon initialization.

The [benilla message-frame API](https://github.com/samwhosung/benilla/blob/main/crates/benilla-ui/src/script/messageframe/scrolling.rs) exposes native fade and scroll controls. Its [message-frame state](https://github.com/samwhosung/benilla/blob/main/crates/benilla-ui/src/widget/kinds/messageframe.rs) rearms displayed-line fade timers on scroll. The addon reveals without copying or rewriting messages: Down at the bottom, or Down followed by Up elsewhere, restores the same scroll position and refreshes displayed lines. Only mouse-wheel scrolling calls this reveal path. Hover and input focus do not change native fading; scrolling back pauses it for reading, and returning to the bottom resumes the normal hold and fade. Optional methods are feature-detected; these primary-source references do not establish the exact packaged client's implementation. Native history is preserved: the addon does not call `SetMaxLines`, which clears that history in the referenced implementation.

## Copy behavior

Type `/copy` to open the Copy dialog, then press Ctrl+C to copy the selected text. While it is open and `/sdui` editing is active, left-drag its body to move it or a corner icon to resize its actual dimensions. Confirm saves the pending geometry and locks the dialog with the other frames. Resizing updates the text wrapping and scroll viewport without scaling fonts. The command is registered in `modules/chat/copy.lua` through `_G.SLASH_SURVIVORSDRAGONUICOPY1` and `_G.SlashCmdList["SURVIVORSDRAGONUICOPY"]`, using the real global table for the native chat parser. It calls `GetCaptureText()` and `ShowCopy` independently of visible chat setup. The dialog contains a snapshot of diagnostics collected for the current UI session, including messages hidden from regular chat. Capture continues while the dialog is closed or open; each `/copy` invocation takes a new snapshot. No Copy button or chat tabs are shown.

`modules/chat/capture.lua` is loaded before chat setup and records independently of native chat subscriptions and formatting. Its own event frame captures supported `CHAT_MSG_*` events, including addon, combat and monster events, plus `UI_ERROR_MESSAGE`, `UI_INFO_MESSAGE` and `PLAYER_LEVEL_UP`. `[EVT]` entries retain the raw message, author and additional event arguments, adapting the supplied source's `/ccdebug` diagnostic coverage for Interface 11200. `[RAW]` entries record original Lua `AddMessage` input from every standard native chat frame before prettifying, hiding announcements or combining level/stat lines. Copies of one event delivered across native frames are collapsed; separate identical calls on the same frame remain recorded. Diagnostic markup pipes are escaped, as in the original debug output, so link/color codes are available to copy as text. Diagnostic entries are not printed into the visible chat.

The session archive has no 512-record cap and is cleared by a UI reload. Completed batches are compacted once into immutable chunks; appending never recopies earlier history. Copy joins those chunks directly with the current native-history snapshot, preserving every record, its order and literal diagnostic markup without another archive-sized table of individual lines or a full-string markup round trip. The ordinary `GetCaptureText` result still escapes diagnostic pipes; Copy requests the equivalent plain result directly. No second complete export is cached between requests.

The Copy dialog retains its complete editable, selectable text. Its hidden wrapping measurer releases its text after reading the height, and one text or geometry revision causes only one measurement. It uses no SavedVariables, settings or new `/ccdebug` command. When the client exposes `GetNumMessages` and `GetMessageInfo`, opening Copy additionally includes a labeled snapshot of retained native history. This exposes bypassing client writes that remain available through those methods; native writes that bypass Lua and have already left the native ring, or are not exposed by the client, cannot be recovered. The event archive and pre-filter Lua capture remain available when native history getters are absent.

## Addon layout policy

The Chat editing outline includes both the message pane and the native input/scroll-indicator strip below it, even while those controls are hidden. Its bounds follow the chat window as it moves or resizes. The saved width and height still describe the message pane; the input placement, font size and visual styling are unchanged.

Chat uses the game's DEFAULT font, with appearance defaults and default geometry defined in code. `/sdui` enters the shared HUD layout editor; repeated calls keep it open. Left-drag a group's body to move player/target frames, boss/guardian bars, run timer, action bar, XP, tally, micro menu, buffs, minimap and chat independently, or left-drag a corner icon to resize the corresponding group. These controls appear only during edit mode, including for hidden HUD groups without showing inactive targets or encounters. The main menu and Copy window support them only while open. Cast-bar and quest-watch displays are removed. The single centered Confirm button stays above all handles, saves the pending geometry and locks the layout, hiding all editing controls. There are no permanent handles or settings panels. Entering editing, moving or resizing chat does not reveal faded history or change fading. Mouse-wheel navigation remains available throughout editing, including its existing SHIFT fast-scroll modifier, and is still the only action that reveals history. Normal native clicks and hyperlinks remain available while the layout is locked. `/copy` remains the only entry to Copy.

HUD groups use independent uniform scale when resized, preserving their artwork proportions. Chat and Copy instead change actual dimensions for text wrapping and viewport layout, retaining their font sizes. Matching action-bar, XP and tally artwork widths describe their defaults; user resizing can make them differ.

Dragging/resizing stages draft geometry without saving on drop. Confirm stores all pending geometry in the single `SurvivorsDragonUiLayout` SavedVariables table: locations, HUD scale and chat/Copy dimensions. That confirmed geometry persists across `/reload` and game sessions in the layout table; SCT mode is saved separately in `SurvivorsDragonUiSctMode`. Unconfirmed edits are discarded on world leave, logout and reload, restoring the last confirmed layout. `/sdui reset` immediately clears saved geometry, discards drafts, exits editing and restores default positions and sizes, including hidden frames. Geometry persistence is separate from the raw diagnostic archive, which remains session-only; it stores no gameplay/native API state, profiles or other configuration. The port does not import the Ace framework, settings windows, profiles or 3.3.5 compatibility layers. `/sdui` opens layout editing; Confirm saves and locks it; `/copy` opens diagnostics; `/sdui reset` restores default geometry; `/sdui` → Combat text selects Custom/Off/Game settings and Confirm saves the combat-text mode across runs, reloads and game sessions, independently of layout reset.

The earlier broad `filters.lua` module is retained as unused source and is not loaded by the TOC. The narrow `prettify.lua` module is loaded for the approved categories only. Message visibility remains independent of capture. The visual skin and animation remain active around the native message renderer.

Original Blizzard 1.12.1 implementation references: [chat dispatch](https://github.com/MOUZU/Blizzard-WoW-Interface/blob/master/1.12.1/FrameXML/ChatFrame.lua), [shared edit box and saved window visibility](https://github.com/MOUZU/Blizzard-WoW-Interface/blob/master/1.12.1/FrameXML/FloatingChatFrame.xml), [dock selection](https://github.com/MOUZU/Blizzard-WoW-Interface/blob/master/1.12.1/FrameXML/FloatingChatFrame.lua), and [native link actions](https://github.com/MOUZU/Blizzard-WoW-Interface/blob/master/1.12.1/FrameXML/ItemRef.lua).

## Validation limit

This integration is edited without addon execution. No validation, tests, syntax checks, AzerothSurvivors startups or WoWSilicon startups are run. These notes record the implementation decisions; they do not claim that rendering, message coverage or runtime behavior has been verified in-game.
