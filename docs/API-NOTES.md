# Official addon API integration — 2026-10-14

The owner announced native addon support in **Azeroth Survivors 0.87.0**, and the user supplied the official `addon_docs.md`. A verbatim copy is saved as `AzerothSurvivors-Addon-API.md` beside this note.

This supplies everything needed for DragonSurvivorsUI's native run-progress and boss-health replacements, including control over the original HUD. Public users install only the addon; the old external REA companion is unnecessary and excluded.

| Purpose                                                                | Official interface                                                  |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Native smooth, pause-aware elapsed time                                | `AZS_GetRunTime()`                                                  |
| Current run lifecycle                                                  | `AZS_GetPhase()`                                                    |
| Actual zone duration/final-boss time                                   | `AZS_GetRunLength()`, with native `AZS_RUN.fin` fallback            |
| Complete boss-spawn schedule; boss-state skull, glow and checkmark display | `AZS_SCHEDULE`, each entry's `at` and `state` |
| Every live boss, with stable identity within a run                     | `AZS_GetBosses()`: `id`, `name`, `hp`, **`hpm`**                    |
| Guardian bars sharing the native boss-HUD group                        | `AZS_GetGuardians()`: `id`, `name`, `hp`, `hpm`                     |
| Kills, current gold and the next cache's gold cost                     | `AZS_RUN.kills`, `AZS_RUN.gold`, `AZS_RUN.chest`                    |
| Show/hide native HUD groups                                            | `AZS_SetHudShown(part, shown)` and `AZS_IsHudShown(part)`           |
| Immediate state/list refreshes                                         | `CHAT_MSG_ADDON`: `AZSZONE`, `AZSRUN`, `AZSBOSSES`, `AZSUNITS`      |

`modules/ui/run.lua` now consumes these APIs directly. There is no invented snapshot global, companion sequence/acknowledgement protocol, independent run clock or heartbeat timeout. The native getter owns interpolation and pauses. The local 0.1-second accumulator only throttles list refreshes.

The official document corrects the earlier assumption that every zone lasts 16 minutes: duration and spawn times are zone-specific. Elwynn Forest remains 960 seconds with spawns at 3, 6, 9, 12 and 16 minutes. Other zones use their native duration and full schedule. The addon validates that full schedule and displays every scheduled skull. Native `due` entries keep the default full-size, opaque skull; `up` entries add a red/orange glow underneath the unchanged skull; `dead` entries use an 80%-size skull at 70% opacity with a green checkmark and no active glow. The checkmark means the boss was killed, based only on the official schedule state. Only the fill is clamped after the final-boss time, allowing elapsed time to continue in endless mode.

Every live boss and engaged guardian has its own spawn-id key and health pill, with no addon-imposed four-row limit. Guardians are shown only when their documented `awake` flag is true (or native numeric 1); sleeping guardians are omitted. This keeps map-wide dormant lairs from bloating the HUD, while engaged enemies remain visible even at full health. Do not use `enraged` (a low-health state), selection or missing HP as an engagement test. The API's `hpm` maximum-health field replaces the private JSON's old `hpMax` field. All returned native lists remain read-only.

The addon hides `clock`, `bosses` and `tally` only after their replacements are ready; `bosses` includes guardians, so engaged guardians' health is also preserved in the replacement. The clock requires a valid phase, native elapsed time and native duration; its marker schedule is independent. It captures prior HUD visibility and restores it when a replacement's required native data is missing/invalid, on world leave and on logout. Saved game HUD settings are not treated as addon configuration.

The replacement tally is one gold bar whose default placement is directly beneath the XP bar, with its default total outer width matching the seven-button action bar artwork and XP bar. Each of those three groups can be moved and uniformly resized independently, so user resizing can make their displayed widths differ. Three equal sections show centered numeric values with in-game icons and DEFAULT text for kills, current gold and the next cache's gold cost. These come directly from `AZS_RUN.kills`, `AZS_RUN.gold` and `AZS_RUN.chest`; `ck` counts opened caches and is not used as a price. All three required counters must be present and nonnegative; zero is valid. Missing fields release control of the native tally. Native `AZSRUN` messages and the existing 0.1-second poll refresh the values without inventing increments or timing out a paused run.

Phase must be read before using retained tables, which can contain previous-run data outside a run. A nil clock before the first update leaves the original HUD available. Paused/unchanged native state is valid without repeated packets.

After `/reload`, each HUD replacement reconnects independently when its required native data arrives. A missing zone-derived run length can fall back to the current run's official `AZS_RUN.fin`; no local clock or guessed schedule is used. Encounter lists must have `AZS_UNITS_UPDATED` before an empty list can suppress native boss bars. The addon cannot request a full API replay: unchanged lists and paused runs need the game to republish its current state after rebuilding the Lua VM. See [RELOAD-API-NOTES.md](RELOAD-API-NOTES.md) for the static evidence, owner-side requirement and unverified live status.

The API also exposes damage-meter lines, damage taken, spells/cooldowns, buffs, other hero/run statistics, targets and unit kinds. Those extra capabilities are available for future work; the current replacements cover run/encounter bars, the tally and their native visibility.

The supplied release announcement establishes the **0.87.0+** requirement. It does not prove the locally installed executable has been updated. The implementation detects unavailable APIs and leaves the native HUD available. No tests, syntax checks, validation or game startups were run for this change, per the project instruction.

## Independent clock and marker recovery after reload — 2026-10-15

The user reported that `/reload` leaves the run progress bar without its vertical boss-spawn markers. A recovered native clock and `AZS_RUN.fin` can supply elapsed time and duration before `AZSBOSSES` has replayed the complete schedule. The first response made the entire clock wait for that schedule; the user then reported that the whole custom top bar disappeared after `/reload`. That schedule gate has been removed from clock display and takeover.

Marker rendering requires a complete valid `AZS_SCHEDULE`, checked against the native expected boss count from `AZS_RUN.bt` or `AZS_ZONE.bt`. Schedule entries need unique numeric indices, positive spawn times no later than the native run length, a recognized `due`, `up` or `dead` state, and a final-boss flag/time agreeing with that length. Completeness validation uses the full list, including every state; `AZS_GetUpcomingBosses()` cannot replace it because that getter excludes past bosses. The native state chooses each marker's default, active-glow or killed-checkmark appearance. Elapsed time and the absence of a live boss entry never establish activation or death. Native tables remain read-only.

The custom clock displays and takes control of the native `clock` HUD part as soon as the phase, native elapsed time and native duration are valid. A missing or incomplete schedule clears only its marker textures; it keeps the progress bar visible and respects the selected run-label visibility without a duplicate native clock. Markers rebuild from the complete official schedule when it arrives, restoring the default skulls for `due`, active glow for `up` and killed checkmarks for `dead`. Invalid phase, elapsed time or duration releases the custom clock and restores captured native visibility, including an originally hidden game preference. Tally and encounter bars continue reconnecting independently when their own native data is ready.

This corrects the full-bar regression while keeping incomplete marker data separate from valid clock data. It does not reconstruct absent spawn times after a Lua VM reload. Official getters remain polled every frame, list refreshes remain throttled to 0.1 seconds, and native addon messages trigger refreshes. There are no invented markers, independent clock, persisted private schedule or resync command. Complete marker restoration still depends on the game replaying the current `AZSBOSSES` snapshot, including while paused or unchanged. See [RELOAD-API-NOTES.md](RELOAD-API-NOTES.md). This edit was made without tests, syntax checks, validation or game startups and has not been verified live.

## Independent layout geometry — 2026-10-15

The user replaced the modifier-key trigger with explicit layout edit mode. `/sdui` opens editing; repeated calls keep it open. Left-dragging a group's body moves it and left-dragging a corner icon resizes it while editing is active. Outlines and corner icons remain visible until editing ends, including for hidden HUD groups without showing inactive targets or encounters. A single centered Confirm button stays above the handles. The remaining groups include independent player/target frames, boss-health group, run timer, action bar, XP, kills/gold/cache tally, micro menu, buffs, minimap and chat, plus the main menu and Copy window while open. Cast-bar and quest-watch displays are removed rather than registered for layout editing.

HUD groups resize by uniform scale, retaining their artwork proportions. Chat and Copy instead change actual width and height to update wrapping and the viewport, while fonts retain their normal size. The defaults remain defined in code, with XP beneath the action bar and tally beneath XP at matching artwork widths; moving or resizing one never changes another. Boss health rows remain together in their own group, independently of the timer.

Moving and resizing stage draft geometry without saving on drop. Confirm stores all pending locations, HUD scale and chat/Copy dimensions in the single `SurvivorsDragonUiLayout` SavedVariables table, then locks the layout and hides its editing controls. Unconfirmed edits are discarded on world leave, logout and reload; the last confirmed layout is restored. `/sdui reset` immediately clears saved geometry, discards the draft, exits editing and restores every registered group's default position and size, including groups that are currently hidden. It does not alter native run data, native HUD visibility preferences or the separately saved `/sct` mode. `/copy` remains the chat-capture utility; raw capture is still session-only. Chat defaults to the bottom-left corner and keeps opacity 0. Entering edit mode, moving or resizing does not reveal faded history or change fading; mouse-wheel navigation remains available during editing and is still the only reveal action. Its existing SHIFT fast-scroll modifier remains unrelated to layout editing.

Layout persistence never stores phase, clock, schedules, encounters, counters or other native API snapshots. The HUD still requires the same official native data and replay described above. These layout edits were made without tests, syntax checks, validation, addon execution or game startups.

## Invisible nameplate tracking for custom SCT — 2026-10-15

The user reported that custom hits fell back to the center when native nameplates were hidden. Custom `/sct on` now separates V's requested visible state from the native tracking state: it uses the original `ShowNameplates` to keep hostile plates live and their coordinates updating even when the user has chosen to hide the plates. `NAMEPLATES_ON` and the user's saved V preference remain unchanged. `/sct off` and `/sct default` release that tracking control and restore the originally requested native visibility. World leave and logout release it too; the selected SCT mode is saved separately and restored on the next UI initialization.

With V off, the addon disables draw layers on hostile plate frames and their descendants, including health-bar layers. It makes their hit rectangles empty through insets so invisible plates cannot receive clicks. It leaves the native mouse-enabled flag unchanged, preserving the client's freelook transitions. It does not hide the plate frames or change their alpha, so their native shown-state lifecycle and coordinate updates continue. Turning visible plates back on, changing out of custom mode, leaving the world or logging out restores the captured draw-layer and hit-rectangle state.

The base source supplies the mechanism: [native nameplate show/hide functions](https://github.com/samwhosung/benilla/blob/main/crates/benilla-ui/src/script/nameplate.rs), [frame draw-layer and hit-rectangle controls](https://github.com/samwhosung/benilla/blob/main/crates/benilla-ui/src/script/object/frame_state.rs), [native plate placement and collision handling](https://github.com/samwhosung/benilla/blob/main/crates/benilla-app/src/vplates.rs), and [native overhead-name behavior](https://github.com/samwhosung/benilla/blob/main/crates/benilla-app/src/nameplates.rs). These primary sources establish the intended integration mechanism, not the exact packaged game's behavior; the implementation has not been verified in-game.

Custom SCT uses live visible or invisible plates and recently retired positions with name/health-change evidence. Unmatched or ambiguous messages still appear at the shared fallback; no destination GUID or exact enemy projection is exposed by this integration. The tracked coordinates retain native collision displacement, so this does not disable native plate stacking. Native overhead enemy names can remain suppressed while the internal native tracker is active, even though the plate layers are invisible. Each hit keeps its independent animation through plate hiding, deaths and frame reuse, and mode changes clear active and queued hits immediately.

This is addon-only integration, with no settings window, companion process or client patch. No tests, syntax checks, validation, addon execution or game startups were run for this change.

The checkmark indicates a killed boss. Passing a scheduled time and disappearing from `AZS_GetBosses()` never establish activation or death. The pause-aware native clock continues to drive elapsed time and progress only; no private clock advances boss state.

Schedule completeness checks include all recognized `due`, `up` and `dead` states; marker positions, the 0.1-second schedule/geometry refresh, native table ownership and independent clock/reload recovery stay unchanged. Missing or incomplete schedules clear the skull, glow and checkmark while keeping a valid clock visible. Unused pooled markers and clock release also hide all three visuals. Replayed schedules after `/reload` and fresh schedules for new runs restore appearance from their official states without persisted private snapshots. ## Saved SCT mode — 2026-10-15

The selected `/sct on`, `/sct off` or `/sct default` mode now persists in the separate `SurvivorsDragonUiSctMode` SavedVariable. Module initialization reads it after addon SavedVariables load, accepts only those three mode names and falls back to custom `on` mode for missing or invalid values. Startup uses the same mode-selection path as the slash command, applying the matching native `CombatDamage` value and nameplate tracking behavior. Each valid selection updates the saved mode; `/sct` help and invalid arguments leave it unchanged.

This supersedes the earlier session-only SCT policy. World entry reapplies the selected mode, while world leave and logout still release internal nameplate tracking and clear hits. `/sdui reset` and **Addon defaults** clear geometry and timer font choices while leaving the SCT preference unchanged. No chat capture, combat hits, plate state, native CVar snapshot or gameplay/API data is persisted. No local checks, tests, addon execution or game startups were run for this edit; in-game persistence has not been verified.

## Run timer font and text editing — 2026-10-15

The user requested font changes for the top `RUN` label while `/sdui` is active. Its editing controls preview font face, size, outline and shadow, with the same Confirm/discard lifecycle as layout geometry. The **Run text** control also previews showing or hiding the entire `RUN elapsed / duration` label while keeping the progress pill and boss markers visible. Only Confirm saves the selected font and normalized boolean `showText` in `SurvivorsDragonUiRunFont`, a separate SavedVariable containing the font/text preference. Missing or invalid `showText` values default to shown so older font saves retain their label. `SurvivorsDragonUiLayout` remains geometry-only. World leave, logout and reload discard unconfirmed font/text edits and restore the confirmed choice. **Addon defaults** calls the shared layout reset used by `/sdui reset`: both immediately clear saved geometry and the timer font/text preference, discard all pending edits, restore every registered group's defaults including hidden groups, show the run label, and exit editing without requiring Confirm. Both leave the separately saved SCT mode unchanged. The font editor can be moved by left-dragging its background while open; its width fits the controls and available font labels. Its position is session-only and adds no SavedVariable or layout entry. The shared full reset also recenters the editor.

The available faces are `DEFAULT` and the four client fonts listed in the [base game's font loader](https://github.com/samwhosung/benilla/blob/main/crates/benilla-app/src/ui_text/engine/faces.rs): `Fonts\\FRIZQT__.TTF`, `Fonts\\ARIALN.TTF`, `Fonts\\MORPHEUS.TTF` and `Fonts\\SKURRI.TTF`. The addon run label defaults to shown in Skurri, size 14, normal `OUTLINE`, and a black shadow at `(1, -1)`. Existing confirmed font preferences remain in use until changed or reset. DEFAULT is initialized before attempting a native face, leaving a readable fallback when it is unavailable. No font assets or machine-specific paths are added. The edit bounds include the selected font's label only while shown; hiding it removes that extra text area. Font/text controls do not change native clock takeover, time, phase, schedule readiness, marker visibility, encounters or tally recovery.

No local validation, tests, syntax checks, addon execution or game startups were run. Native-font loading and editing behavior in the packaged game remain unverified.
