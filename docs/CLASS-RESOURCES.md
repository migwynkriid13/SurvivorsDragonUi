# Class resources

The player frame deliberately keeps one uninterrupted health bar. A separate layout group now displays the two requested class mechanics: warlock soul shards and rogue combo points. It defaults on beneath the player's health area, with five empty sockets and one filled socket per complete 20 resource units, capped at five. For example, 19 units lights no slots, 20 lights one, 59 lights two and 100 lights five. Partial units do not light another slot. This conversion matches the native power publication in the inspected Survivors v0.94.2 Windows build; it is not ordinary WoW mana, energy or inventory soul shards.

## Current native values

`modules/unit/resources.lua` reads `AZS_GetPhase()` before displaying anything. Only `playing`, `choosing` and `paused` are eligible. It uses the current native `UnitClass("player")` token rather than retained `AZS_ZONE.class`, so a missing once-per-run zone replay after reload does not itself block recovery. Warlocks require native power type `0` (mana), rogues `3` (energy), an existing player, finite nonnegative current power and a finite positive maximum. Disabling class resources, other classes, unavailable values, ready/dead/victory and world leave/logout hide and clear the row. With class resources enabled, five empty sockets remain visible at zero during eligible runs.

In the [base client's native bindings](https://github.com/samwhosung/benilla/blob/129b3bb852b2f328de529f3c698595c14baf5fa5/crates/benilla-ui/src/script/unit/bindings.rs), `UnitMana` and `UnitManaMax` read the current power type, including energy. The module clamps current power to its native maximum and 100, then divides by 20 and rounds down. It never normalizes by maximum power. The base client's `GetComboPoints()` is target-dependent and reads a different native combo state; this module does not use it, derive points from attacks or require a selected target. The official supplied Survivors API has no separate shard/point field. The public base source supports the API choice. Inspection of the supplied game executable now independently confirms the 20-unit encoding for the specific build recorded below.

Player mana/energy, maximum-power and display-power events trigger immediate reads, as do world entry and the official zone/run message prefixes. The [base client's field-event routing](https://github.com/samwhosung/benilla/blob/129b3bb852b2f328de529f3c698595c14baf5fa5/crates/benilla-app/src/ui_unit/field_events.rs) supplies the player token on those unit events. An independent controller polls every 0.1 seconds while the visual row is hidden too, covering delayed phase/class/power initialization. There is no independent resource timer, spell-name matching, native-state mutation or gameplay persistence.

## Native game-code verification — 2026-10-16

The supplied Windows executable reports **v0.94.2 (cb46a4f8)**. Its SHA-256 is `69caa6d39e1db92477227d461dc72cffbb90fd3fa2c679b906e0c2310d22d841`. Static inspection of that executable's native machine code confirms the conversion independently of the earlier reported mechanic. No executable, game assets or disassembly are included in this addon.

The native resource-publication path reads the rogue combo counter and multiplies it by 20 at relative virtual address `0x05457B7B`, selecting update field `0x1A` (`UNIT_FIELD_POWER4`, energy). The corresponding warlock path reads the shard counter and multiplies it by 20 at `0x05457BCB`, selecting field `0x17` (`UNIT_FIELD_POWER1`, mana). Each multiplication is a shift left by two followed by multiplication by five. Both paths publish the resulting value through the same native field-update path. The counter handlers cap accumulation at five and reset the counters when their respective finisher triggers.

The native class records select energy type `3` for rogue and mana type `0` for warlock. The player initializer sets the corresponding maximum-power fields to 100. Consequently, the addon's inverse conversion, `floor(min(currentPower, maximumPower, 100) / 20)`, matches this build's published values: 0, 20, 40, 60, 80 and 100 represent zero through five points or shards. `UnitMana` is the 1.12 name for the active power getter; rogue energy is read through that function too. No attack counting, resource timer or maximum-power percentage is needed.

This establishes the native encoding in the identified executable. It does not establish startup event ordering, that every transient five-point value remains visible before consumption, or resource rendering and reload behavior in a running addon. Other game builds need their own evidence if the native encoding changes.

## Display preference

The **Class resources: on/off** control appears in the existing `/sdui` panel alongside boss debuffs, damage icons and independent Cache/Guardian guidance. It defaults to **on**. Turning it off hides the resource row and restores the previous health-only appearance without changing frame geometry or the selected SCT mode. Changes preview live while editing; **Confirm** alone saves the choice. World leave, logout and `/reload` discard unconfirmed changes and restore the last confirmed value.

The choice is one of five normalized booleans in the existing `SurvivorsDragonUiDisplay` SavedVariable: `classResources`, `bossDebuffs`, `damageIcons`, `cacheGuidance` and `guardianGuidance`. Missing or invalid `classResources` values use `true`, so existing display saves keep the new row enabled by default. Both `/sdui reset` and **Addon defaults** use the existing shared full reset to restore class resources on, boss debuffs on, damage icons off and both guides on, together with layout and timer defaults; the selected SCT mode remains unchanged. No separate reset path is added.

## Layout

`classResources` is its own group in the shared `/sdui` editor. Moving or scaling it does not change player, target, action-bar or other geometry. Its edit outline remains available while its actual resource display is hidden, including when the display preference is off; editing never fabricates filled slots. Confirm alone saves its position/scale in the existing geometry store, separately from the display boolean. Discard and both full resets use the shared layout flow. No extra commands, profiles or SavedVariables are introduced. Existing health-only player/target frames and hidden mana/energy bars remain as before.

## Verification boundary

The native conversion was verified by static inspection of the supplied executable. The game was opened only to its character-selection menu to identify the version; no run was started and no addon interaction was exercised. No local addon tests, syntax checks or formatting tools were run. The existing PR workflow runs its authorized formatting, local dead-code and TOC metadata checks in GitHub Actions. Those checks do not establish packaged-game rendering, native event ordering, resource transitions, reload recovery or layout interaction. Those runtime behaviors remain unverified.
