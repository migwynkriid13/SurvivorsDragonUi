# Cache and guardian waypoints

Cache and guardian waypoints add independent guidance HUDs and clickable world-map pins using the official coordinates supplied in the owner's updated addon documentation on 2026-10-15. Cache guidance requires `AZS_CHESTS` and `AZS_CHESTS_UPDATED`; guardian guidance requires `AZS_LAIRS` and `AZS_LAIRS_UPDATED`. Both require the native active run phase. Zone/map identity is additionally required for map geometry. Install them as part of SurvivorsDragonUi; no companion process or client modification is required.

## Player behavior

- Available caches receive Blizzard's actual tracked-waypoint diamond artwork on the world map.
- Guardian world-map pins use the Dragonflight rare-elite marker: a gold star with a silver dragon. Show every living guardian's occupied lair, including asleep guardians and guardians currently fighting. Empty or refilling lairs have no guardian pin, and a guardian's old pin disappears when it dies or is replaced.
- Each guide selects a nearby destination automatically when the player's location can be read. While position data is unavailable, the first available destination keeps that overlay visible with "On map"; automatic selection retries until it can choose a nearby one. A resolved cache selection stays until the cache is opened or disappears; a guardian selection stays until that guardian's occupied-lair identity disappears. Click another map pin of either kind to select it independently.
- Each waypoint has its own true square frame preserving the original pill's textured gold border, beveled corners and straight edges. Eight original artwork slices retain fixed corner proportions; only straight middle sections stretch. At art scale 1.5 the corners are 16.5 by 10.5 and the visible gold rim is three pixels thick. Additive blending at 0.9 alpha removes the black outer shadow, and seven `BackgroundCenter` strips at 0.45 alpha fill the inner cut-corner contour without background caps. Each side is 95% of the combined DEFAULT action-bar artwork and XP border height. This uses static appearance metadata, so independently moving or resizing the action bar or XP does not enlarge the squares.
- Cache defaults to the left of that action-bar/XP stack and **Guardian** to the right, vertically centered on its combined artwork span with an eight-unit horizontal gap beyond the artwork edges. Registration waits for the bar/XP appearance metadata, after which shared layout handling converts these defaults to independent UIParent positions. Confirmed custom positions remain in use, and unrelated layout stays untouched.
- Content is stacked inside each square. The top graphic row pairs the marker with an 18-by-18 direction triangle rotating in place beside it. The cache keeps its original gold `HudDiamond.tga` at 14 by 20, and the guardian keeps its Dragonflight rare-elite marker (a gold star with a silver dragon) at 20 by 20. The full Cache or Guardian label is centered beneath in DEFAULT 9, in a region `side - 8` wide and 12 high; distance sits at the bottom in DEFAULT 10, also 12 high. Both show straight-line horizontal distance in yards when native map geometry establishes the scale.
- Guardian coordinates describe the fixed lair, not the guardian's moving combat position. The visible label is **Guardian**; its distance and direction still refer to the lair, including while its guardian is fighting elsewhere.
- Move and uniformly resize each square independently through `/sdui`, then click Confirm to save geometry. Uniform resizing keeps both dimensions equal. Their existing layout keys remain `cacheWaypoint` and `guardianWaypoint`. Each frame hides with its own unavailable waypoint; the two containers remain separate. Unconfirmed geometry uses the existing discard behavior. `/sdui reset` and Addon defaults restore both default anchors and sizes. The containers add no settings or SavedVariables.
- Selection, positions and map calibration are session-only. No cache, guardian or other gameplay state is added to SavedVariables.

## Data and geometry

Default appearance metadata defines the square size and anchors: action artwork top is `55 + native action-button height + 14`; XP border bottom is `49 - (6 + 12) / 2 = 40`. Each side is `0.95 * (action top - XP bottom)`, with the vertical center at that span's midpoint. The left/right horizontal center offsets from the default bar center are `bar width / 2 + 6 + 8 + side / 2`. These are default appearance facts, not measurements of independently moved or scaled live HUD groups.

The renderer copies each cache's official run-local `id`, world `x`/`y` and map `mx`/`my` without mutating or sorting the native lists. It reads phase before retained tables and hides guidance while ready/between runs or dead. A numeric `AZS_CHESTS_UPDATED` identifies a received snapshot; an initially empty placeholder is not treated as confirmed data. On initial loading after `/reload`, the stream's own stamped data can restore guidance before zone data arrives. A received empty list removes all cache pins. Cache and zone last-change timestamps are independent: no ordering across packet prefixes is used to accept or reject a snapshot. Paused and unchanged data remains valid indefinitely, without a stale-feed timeout.

An observed active-to-inactive transition or world leave clears guidance and blocks the old raw table reference until a replacement table or matching `AZSCHESTS` packet confirms new receipt. Once zone context is established, a later `AZSZONE` or zone-identity change retires the last accepted reference unless that stream's matching prefix has been received since acceptance. This preserves a fresh destination snapshot arriving in the same event batch as its zone update. Initial zone-data arrival does not create a new requirement to wait for another destination snapshot.

These are best-effort protections around observed boundaries. The native API has no run id, so the addon cannot prove full run identity or reliably detect a boundary it never observed. It does not persist private snapshots to conceal that limitation.

Guardian guidance follows the same snapshot and lifecycle rules independently through `AZS_LAIRS`/`AZS_LAIRS_UPDATED` and `AZSLAIRS` packets. It accepts only `asleep` or `awake` lairs with a positive guardian `id`; both states represent a living guardian. Each copied record uses `index` plus guardian spawn `id` for identity and the lair's official coordinates for geometry. A replacement guardian in the same lair receives a new identity. Empty/refilling lairs are omitted, and a received empty or unoccupied list removes guardian pins. The addon never estimates a living guardian's current position from its lair or changes its selection through gameplay actions.

Native `GetWorldLocMapPosition(mapId, x, y)` projects cache and lair positions onto the map the player is browsing, including wider sheets when supported. The addon never changes the world-map selection while it is open. If that native getter is absent or cannot project a point, official normalized coordinates are used only when the selected sheet matches the player's known current-zone sheet. Unknown/off-map positions are hidden.

Both HUDs read player map coordinates and the native minimap player-arrow model's facing. Geometry calibration consumes only copies accepted by the renderer's snapshot/lifecycle rules; navigation never independently reads the raw cache or lair lists. Native world-to-map projection probes can determine the zone's physical axis spans from one accepted cache or lair point. When those probes cannot establish scale, distinct accepted official world/map coordinate pairs can establish it. Observed boundaries clear calibration along with rejected destination data. Unknown scale hides direction arrows and never produces a fabricated yard distance. Both guides keep their central marker and destination/distance text visible. Neither feature adds minimap icons or indicators.

## Artwork and limits

The world-map cache pin, central navigation diamond and direction triangle are actual Blizzard waypoint/navigation textures, not generated substitutes. World-map pin artwork stays unchanged. See [CacheWaypoints-ARTWORK.md](../third_party/CacheWaypoints-ARTWORK.md) for their pinned download sources, Dragonflight UI references, conversion details and attribution. Their texture archive snapshot is 9.2.7, and the corresponding atlas names are referenced by the pinned Dragonflight 10.2.7 UI source. Guardian guidance uses the Dragonflight rare-elite marker, a gold star with a silver dragon; its source attribution is maintained separately in that artwork document.

This implements map pins and HUD guidance. It does not project icons above caches or guardians in the 3D world; no such camera/projection API is documented. It also does not calculate walkable routes, account for walls or provide vertical navigation. Guardian guidance does not track a moving guardian beyond the fixed lair coordinates exposed by the API.

Missing native snapshots, player position, heading or map geometry hide the affected guidance rather than inventing it. `AZSCHESTS` sends the full remaining-cache list whenever it changes, including cache spawns and openings. `AZSLAIRS` updates occupied, fighting and empty/refilling lair state; only occupied living-guardian records become destinations. After `/reload`, the game must reinstall/replay the relevant official API state, including when paused or unchanged. Each received destination snapshot can restore its HUD even before zone geometry replays, but a missing cache or lair snapshot must wait for another native update. There is no documented addon-side resync request, and cache/guardian gameplay data is not persisted across reloads.

No local validation, tests, syntax checks, formatting tools, addon execution or game startups were run. The integration remains unverified in the packaged game.
