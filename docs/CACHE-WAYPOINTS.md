# Cache and guardian waypoints

Cache and guardian waypoints add independent guidance HUDs and clickable world-map pins using the official coordinates supplied in the owner's updated addon documentation on 2026-10-15 and the subsequent `AZS_RUN` world-position/facing update. Cache guidance requires `AZS_CHESTS` and `AZS_CHESTS_UPDATED`; guardian guidance requires `AZS_LAIRS` and `AZS_LAIRS_UPDATED`. Both require the native active run phase. Received `AZS_RUN.px`/`py` and `pf` supply direct world guidance on supported builds, including instances; zone/map identity is additionally required for map projection and the older map-based fallback. Install them as part of SurvivorsDragonUi; no companion process or client modification is required.

## Player behavior

- Available caches receive Blizzard's actual tracked-waypoint diamond artwork on the world map.
- Guardian world-map pins use the Dragonflight rare-elite marker: a gold star with a silver dragon. Show every living guardian's occupied lair, including asleep guardians and guardians currently fighting. Empty or refilling lairs have no guardian pin, and a guardian's old pin disappears when it dies or is replaced.
- Each guide selects a nearby destination automatically when the player's location can be read. While position data is unavailable, the first available destination keeps that overlay visible with "On map"; automatic selection retries until it can choose a nearby one. A resolved cache selection stays until the cache is opened or disappears; a guardian selection stays until that guardian's occupied-lair identity disappears. Click another map pin of either kind to select it independently.
- Each waypoint has its own horizontal floating-label guide, 190 by 46 at its default size. An upright 32-by-32 icon sits beside two left-aligned text lines: the full Cache or Guardian title in DEFAULT 13 above distance in DEFAULT 15. The guardian HUD uses the gold-dragon/skull medallion `GuardianFloating.tga`, and the cache HUD uses `CachePouch.tga`. A fine muted-gold stripe sits along the bottom. The icon and text have transparent backgrounds, with no rectangular fill or enclosing border.
- Cache defaults to the left of that action-bar/XP stack and **Guardian** to the right, vertically centered on its combined artwork span with an eight-unit horizontal gap beyond the artwork edges. Registration waits for the bar/XP appearance metadata, after which shared layout handling converts these defaults to independent UIParent positions. Confirmed custom positions remain in use, and unrelated layout stays untouched.
- The full native navigation arrow from `HudArrow.tga` rotates in place to the right of the text. Its visible width is `19 * 1.2 = 22.8`, 20% larger than the selected floating-label preview. The original texture has a 24-pixel-wide glyph on a 32-pixel canvas, so the full canvas draws at `19 * 1.2 * 32 / 24 = 30.4` square; the icon and text stay upright. Both guides show straight-line horizontal distance in yards from native world coordinates when available, otherwise when native map geometry establishes the scale.
- Guardian coordinates describe the fixed lair, not the guardian's moving combat position. The visible label is **Guardian**; its distance and direction still refer to the lair, including while its guardian is fighting elsewhere.
- Move and uniformly resize each guide independently through `/sdui`, then click Confirm to save geometry. Uniform resizing preserves the 190:46 shape. Their existing layout keys remain `cacheWaypoint` and `guardianWaypoint`. Each guide hides with its own unavailable waypoint; the two containers remain separate. Unconfirmed geometry uses the existing discard behavior. `/sdui reset` and Addon defaults restore both default anchors and sizes. The two visibility choices share the existing display preference store; no separate SavedVariables are added.
- **Cache guidance: on/off** and **Guardian guidance: on/off** in `/sdui` independently control each guide's HUD and world-map pins, both defaulting on. Guardian guidance also controls the native-flag skull replacement described below. Changes preview immediately. Confirm alone saves `cacheGuidance` and `guardianGuidance` in `SurvivorsDragonUiDisplay`; missing or invalid older choices default on. Turning a guide off keeps its valid destination, accepted snapshots, calibration and geometry, and its layout handles remain available. Turning it back on restores the current valid selection. World leave/logout/reload discard unconfirmed visibility drafts. Both full resets restore both guides on together with their default geometry.
- Selection, positions and map calibration are session-only. No cache, guardian or other gameplay state is added to SavedVariables.

## Data and geometry

Each guide defaults to `HUD_WIDTH = 190` and `HUD_HEIGHT = 46`. Default appearance metadata supplies the anchors: action artwork top is `55 + native action-button height + 14`; XP border bottom is `49 - (6 + 12) / 2 = 40`. The vertical center remains at that combined artwork span's midpoint. The left/right horizontal center offsets from the default bar center are `bar width / 2 + side inset 6 + gap 8 + HUD_WIDTH / 2`. Registration waits for this static metadata and lets shared layout convert the defaults to independent UIParent positions. Moving or resizing live action-bar or XP groups does not change the guides' dimensions or default anchor calculations; confirmed custom waypoint geometry and unrelated layout remain in use.

The renderer copies each cache's official run-local `id`, world `x`/`y` and map `mx`/`my` without mutating or sorting the native lists. It reads phase before retained tables and hides guidance while ready/between runs or dead. A numeric `AZS_CHESTS_UPDATED` identifies a received snapshot; an initially empty placeholder is not treated as confirmed data. On initial loading after `/reload`, the stream's own stamped data can restore guidance before zone data arrives. A received empty list removes all cache pins. Cache and zone last-change timestamps are independent: no ordering across packet prefixes is used to accept or reject a snapshot. Paused and unchanged data remains valid indefinitely, without a stale-feed timeout.

An observed active-to-inactive transition or world leave clears guidance and blocks the old raw table reference until a replacement table or matching `AZSCHESTS` packet confirms new receipt. Once zone context is established, a later `AZSZONE` or zone-identity change retires the last accepted reference unless that stream's matching prefix has been received since acceptance. This preserves a fresh destination snapshot arriving in the same event batch as its zone update. Initial zone-data arrival does not create a new requirement to wait for another destination snapshot.

These are best-effort protections around observed boundaries. The native API has no run id, so the addon cannot prove full run identity or reliably detect a boundary it never observed. It does not persist private snapshots to conceal that limitation.

Guardian guidance follows the same snapshot and lifecycle rules independently through `AZS_LAIRS`/`AZS_LAIRS_UPDATED` and `AZSLAIRS` packets. It accepts only `asleep` or `awake` lairs with a positive guardian `id`; both states represent a living guardian. Each copied record uses `index` plus guardian spawn `id` for identity and the lair's official coordinates for geometry. A replacement guardian in the same lair receives a new identity. Empty/refilling lairs are omitted, and a received empty or unoccupied list removes guardian pins. The addon never estimates a living guardian's current position from its lair or changes its selection through gameplay actions.

Native `GetWorldLocMapPosition(mapId, x, y)` projects cache and lair positions onto the map the player is browsing, including wider sheets when supported. The addon never changes the world-map selection while it is open. If that native getter is absent or cannot project a point, official normalized coordinates are used only when the selected sheet matches the player's known current-zone sheet. Unknown/off-map positions are hidden.

Navigation reads the received `AZS_RUN` snapshot, gated by an active native phase and numeric `AZS_RUN_UPDATED`. Finite numeric `px` and `py` share the caches' and lairs' world coordinate system in yards: X points north and Y points west. The destination offset is therefore east = `py - target.y`, north = `target.x - px`; horizontal distance is the square root of the sum of their squares. Zero coordinates are valid. The published `pz` is height, but these guides retain horizontal distance and do not use it for vertical navigation. Finite numeric `pf` supplies native facing in radians, zero north and increasing counterclockwise, including zero itself. The existing arrow rotation combines this heading with the destination bearing.

Direct world distance, nearest-destination selection and facing do not need `GetPlayerMapPosition`, a selected map sheet, map-scale calibration, a minimap model or zone metadata. They remain available while browsing another map and on instance maps, including Scarlet Monastery, Blackrock Mountain, Naxxramas and Ahn'Qiraj, when the game publishes the new fields and destination snapshots. Navigation reads the native values without predicting movement or persisting player position. Paused or unchanged received data remains valid without a timeout. Projection accepts the official current zone/map identity rather than restricting it to a fixed zone list; this does not guarantee that every instance has a projectable world-map sheet.

## Smooth HUD updates

The HUD's `OnUpdate` already runs every rendered frame, but repeating a received `AZS_RUN` position does not make that packet's coordinates live. The earlier world-coordinate change preferred those sampled values even where a native per-frame position was available, making the rounded yard label and arrow step at the packet cadence.

Visible guides now first try the native current-sheet player map position with confirmed physical map geometry, and the native minimap model's per-frame facing. These live readings update the displayed distance and direction every frame. Browsing another sheet, missing scale or unavailable instance map coordinates retains the official world-coordinate path; missing native facing retains `pf`. The addon never changes an open world map to obtain a live reading.

For sampled values only, each guide blends its display distance, bearing and heading toward the latest received values on every frame. The transition uses the interval between that stream's run snapshots, capped at 0.5 seconds; angular changes take the shortest turn across north. Each transition stops at its received endpoint without extrapolating speed or predicting movement. Rounded whole-yard labels and their localized units remain unchanged. Native snapshot and map values remain the inputs to automatic selection and pins; interpolation affects only presentation.

First readings, source switches, changed destination identity/coordinates, non-playing phases, frame gaps over 0.5 seconds, new sample gaps over one second and offset changes over 32 yards snap to current data. Missing values clear their affected interpolation channels; hidden or removed guides and world/run cleanup clear all guide paint state. Pause/choosing/victory never continues a movement tween. Unchanged or paused snapshots remain valid; these animation reset limits do not expire destinations or hide valid data. All interpolation state stays in memory with no new controls, assets or SavedVariables. Snapshot-only instances still depend on the game's publication cadence for fresh measurements; display blending does not increase that cadence.

Older builds or missing/invalid fields retain the existing fallbacks independently: player map coordinates plus native geometry for offsets/distance, and the native minimap player-arrow model for heading. Geometry calibration consumes only copies accepted by the renderer's snapshot/lifecycle rules; navigation never independently reads the raw cache or lair lists. Native world-to-map projection probes can determine the zone's physical axis spans from one accepted cache or lair point. When those probes cannot establish scale, distinct accepted official world/map coordinate pairs can establish it. Observed boundaries clear calibration along with rejected destination data. Unknown fallback scale hides direction arrows and never produces a fabricated yard distance. Both guides keep their central marker and destination/distance text visible. Caches have no minimap indicator; the guardian flag replacement below is separate from these HUDs.

## Guardian minimap flag replacement

The owner's 0.102.0 changelog adds `AZS_SetHudShown("flag", false)`, `AZS_GetFlaggedLair()` and each lair's `flag` field. On supporting builds, Guardian guidance replaces the red flag with one upright native skull at the flagged living guardian's lair. Both asleep and awake guardians qualify; empty/refilling lairs do not. This follows the game's flagged destination, independently of the existing world-map selection and floating Guardian HUD. The snapshot reader copies flag metadata with the accepted lair index and guardian spawn id; it never independently reads a raw lair list or infers the target from proximity.

The skull uses `Interface\\TargetingFrame\\UI-TargetingFrame-Skull` and is parented to `Minimap`, inheriting the user's confirmed minimap position and scale. Its position uses the accepted lair and native player offsets in yards. It stays upright and clamps inside the square map edge when its destination is out of range. This is a fixed-lair marker, including while the guardian fights elsewhere; it cannot track the moving creature from these coordinates. No cache markers, additional lair markers, new settings or SavedVariables are added.

The reference [Survivor UI release](https://github.com/morderous/survivor-ui/releases/tag/v3.0.11) demonstrates custom texture overlays; its [pinned MapPins implementation](https://github.com/morderous/survivor-ui/blob/5a63e4fe75d86d4be8b020a9499860aa466709f1/SurvivorUI/MapPins.lua) identifies the native destination with `flag == 1`. No code or artwork is imported. The new getter is feature-detected without assuming its undocumented return shape. Geometry comes from the [native renderer's zoom constants](https://github.com/samwhosung/benilla/blob/a6dbffd8e7591b3d400ac1c9a2b0d5e0d7f50b59/crates/benilla-ui/src/widget/kinds/mod.rs#L941-L958): outdoor diameters are chunk counts 14, 12, 10, 8, 6 and 4 times one 33.3333-yard chunk; indoor diameters are 300, 240, 180, 120, 80 and 50 yards.

The client has no Lua indoor-mode getter. Distinct `minimapZoom` and `minimapInsideZoom` settings let `Minimap:GetZoom()` identify the active mode. When equal, a guarded runtime measurement steps the active zoom once, reads which setting changed and restores the original zoom before rendering. It verifies restoration and caches the result until a world, zone or minimap mode/zoom event. It does not guess that an instance or unavailable world-map sheet means indoors, change the user's world-map selection or measure on every frame. Missing APIs, unknown geometry or an unsuccessful measurement keep the native flag available.

Native flag visibility is captured only when a valid replacement can draw and is restored when the replacement loses its data/geometry, Guardian guidance is turned off, the minimap is hidden, a run/world ends or the UI reloads. Turning Guardian guidance off therefore returns to the prior native flag preference. Visibility drafts do not discard accepted snapshots or the existing waypoint selections. Reload restoration happens before native preference serialization. The replacement remains unverified in the packaged game; local checks and game/addon execution were intentionally not run.

## Artwork and limits

World-map pin artwork stays unchanged: caches use the Blizzard tracked-waypoint diamond, and guardians use `Guardian.tga`, the Dragonflight rare-elite marker with a gold star and silver dragon. HUD artwork is separate: `GuardianFloating.tga` supplies the gold-dragon/skull medallion, `CachePouch.tga` supplies the loot pouch, and the full native `HudArrow.tga` supplies the rotating direction arrow. These are conversions or crops of existing artwork. See [CacheWaypoints-ARTWORK.md](../third_party/CacheWaypoints-ARTWORK.md) for their pinned download sources, Dragonflight UI references, conversion details and attribution. The existing waypoint texture archive snapshot is 9.2.7, and the corresponding atlas names are referenced by the pinned Dragonflight 10.2.7 UI source.

The continuous one-pixel gold stripe uses the native `WHITE8X8` texture with a uniform color and ordinary alpha blending. Its position, RGB `(186, 148, 87)` and alpha `85 / 255` preserve the former rail's baseline while the rectangular dark fill is removed. See the artwork notes for drawing details.

This implements map pins and HUD guidance. It does not project icons above caches or guardians in the 3D world; no such camera/projection API is documented. It also does not calculate walkable routes, account for walls or provide vertical navigation. Guardian guidance does not track a moving guardian beyond the fixed lair coordinates exposed by the API.

Missing native snapshots, player position or heading hide the affected guidance rather than inventing it; map geometry is needed only for projection and fallback guidance. `AZSCHESTS` sends the full remaining-cache list whenever it changes, including cache spawns and openings. `AZSLAIRS` updates occupied, fighting and empty/refilling lair state; only occupied living-guardian records become destinations. After `/reload`, the game must reinstall/replay the relevant official API state, including when paused or unchanged. Received run and destination snapshots can restore direct guidance before zone geometry replays, but a missing cache or lair snapshot must wait for another native update. There is no documented addon-side resync request, and cache/guardian gameplay data is not persisted across reloads.

No local validation, tests, syntax checks, formatting tools, addon execution or game startups were run. The integration remains unverified in the packaged game.
