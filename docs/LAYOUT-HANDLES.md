# Layout handles and alignment grid

`/sdui lock` enters the existing layout editing session with move/resize handles and the same shared Confirm button, centered in the middle of UIParent. It does not create or show the settings dialog on first use. Clicking a handle does not open it either. The button retains the editor's normal artwork, dimensions and confirmation action.

`/sdui` shows the full editor within the same session. Switching either way retains staged geometry and display, timer and combat-text drafts. Entering handles-only mode discards unapplied numeric text, while keeping geometry already staged with Apply or pointer editing. Confirm saves the session and hides the handles. World leave, logout and reload retain the existing draft-discard behavior; neither command adds a saved mode or window position.

Both modes show a screen-wide alignment grid behind the HUD and editing controls. Squares are 32 UI units apart, measured outward from the exact screen center, with stronger lines every four squares. The horizontal and vertical center axes are gold and two physical pixels thick; other lines are one physical pixel thick. During Shift-drag, faint eight-unit subdivisions appear and the frame's edges and center can align with the grid, nearby edit outlines or matching screen edges/center. Two thin gold lines show the active horizontal and vertical alignments. Releasing Shift restores free movement and hides the guides and subdivisions. The grid overlay remains mouse-transparent.

Body dragging uses the original cursor-to-frame offset in UIParent units. Each update derives a fresh owner position from that sample, then measures the actual edit `region`, including inherited scale and offsets. This keeps alignment tied to the compact Level Up panel, extended action artwork and other visible edit bounds. Snapping never changes another group's geometry. Corner resizing and numeric input retain their existing behavior.

Each axis considers the moving region's two edges and center. Screen candidates match the same edge or center, keeping the full region on screen when seated at an edge. Other edit outlines offer all edge/center pairings when their perpendicular spans overlap or are within 96 UI units. Candidate availability shares the handle renderer's rules, so closed windows and inactive detached groups do not create invisible magnets; the normal handles for inactive HUD groups remain eligible. The closest screen/frame alignment within eight UI units captures before grid fallback. A captured alignment holds until twelve units away, or until its perpendicular gap exceeds 128 units, so nearby competing points do not flicker. Unavailable targets release immediately.

Grid fallback chooses the closest edge/center alignment on the eight-unit subdivisions derived from `GRID_SPACING / 4`. Exact half-step ties round away from the screen center. The renderer shares that spacing and pools subdivision textures. Two pooled native `WHITE8X8` guide textures cache their position, viewport and physical-pixel size. No snapping preference or target identity is saved; the latch lives only in the current drag.

Only an active Shift-drag measures snap targets; free movement does not scan them. The release handler applies the current cursor/modifier state before capturing the position, including a release between update frames. A viewport/scale transition finishes at the last valid position. Releasing Shift, ending the drag or closing editing clears the guides and magnetic hold. Movement remains a draft until Confirm; Cancel, world/logout/reload discard and both resets use the existing lifecycle. Profiles retain snapped geometry through the same normalized coordinates, without extra layout fields.

`core/layout.lua` lazily creates the grid from pooled native `WHITE8X8` textures. It uses `GetLocalSize(UIParent)` for rendered extents and effective UI scale for line thickness. While editing, viewport/scale changes or entering/leaving Shift-drag rebuild grid geometry; surplus lines hide and later sessions reuse the pool. The shared close path hides it immediately on Confirm, Cancel, either reset, world leave, logout or reload discard. Invalid numeric input keeps the existing session and its grid open. Switching between `/sdui` and `/sdui lock` keeps the same centered grid. It adds no asset, setting, SavedVariable or layout entry.

`core/layout.lua` owns the session, mode, handles and Confirm button. The settings dialog registers one visibility callback; run-font editing still owns its existing previews and saving. This separates showing the dialog from beginning its drafts without another confirmation control or parallel layout store. A closed session clears the handles-only mode, so ordinary `/sdui` continues to open the full editor.

No local checks, tests, syntax/formatting tools or addon/game execution were run. GitHub Actions supplies the authorized static checks; live input and appearance remain unverified.
