# Hover tooltips

## Appearance and scope

Unit, ability and other native `GameTooltip` hovers share a dark, thin rounded-border card, adapted from [PentSec/DragonUI's tooltip module](https://github.com/PentSec/DragonUI/blob/623eca5893c9d475a7b77bd25808bdbe801d247c/DragonUI/modules/tooltip.lua). The five equipped jewelry sockets use a separate frame with the same skin. There is no bronze editor border, gold divider or speech-bubble pointer on jewelry hovers.

The native unit tooltip keeps its normal name, subtitle/guild, level and type details. Valid player class colors tint the name and border; NPC borders use the native friendly, neutral or hostile reaction, with a neutral gray-blue fallback when no color is available. Other native tooltips and the jewelry card use the neutral border.

The user explicitly excluded DragonUI's **Targeting** line and **hover health bar**. The module adds no tooltip rows and hides only `GameTooltipStatusBar`, including subsequent native attempts to show it. Player/target HUD health bars and all native health values are untouched. No substitute health bar, targeting text, spacer or footer is created.

Ability descriptions, prices, cooldowns and native content remain generated by the game. The module keeps native content builders, dimensions and wrapping. Shared hover cards close immediately when the hover ends. By default, buff and debuff tooltips follow below their icons. Skill, character equipment, boss skull and kills/gold/cache-cost tooltips follow above their icons; other native hovers use the shared layout position. The optional cursor mode moves these cards and equipped jewelry hovers beside the mouse cursor. Scale and visibility use the shared layout editor for both.

## Layout controls

**Tooltip at cursor** in `/sdui` → **Tooltip** defaults off. Its normalized `tooltipAtCursor` boolean lives in the existing display table. The shared display editor supplies preview, Confirm-only saving, Cancel/world/logout/reload discard, profile copies and both resets to off. Enabling it uses the current cursor position for shared native hovers, including registered icons and the added timer buffs, and the separate equipped-jewelry card. Saved Tooltip geometry is retained; turning it off restores the current icon or saved placement.

**Tooltip** is a passive 240-by-64 edit region under `/sdui` and `/sdui lock`, available even without an active hover and while the group is hidden. Clicking its handle selects the shared Layout controls: drag to move, resize proportionally, enter coordinates/scale or use **Hide frame**. Except for registered icon hovers, the native card's bottom-right corner follows the region's bottom-right corner, so longer content grows upward and leftward without moving the saved handle. Defaults use the original bottom-right inset of 13 horizontal and 64 vertical UI units, at the tooltip's initial scale.

Native `GameTooltip:IsOwned(button)` selects registered icons directly. This includes the seven action buttons, with the seventh mapped to native slot 12, and every armor, jewelry, weapon, ranged/relic and ammo slot in the C character window. The action and character modules retain their existing button registries and slot lists. One shared ownership helper and placement path serve these and the additional registered HUD icons. Skill, equipment, boss skull and counter cards anchor their bottom center 12 tooltip units above the icon's top center. Player buffs/debuffs, temporary weapon enchants, target and target-of-target auras and encounter debuffs register with the shared `below` side: the card's top center anchors 12 tooltip units below the icon's bottom center. Both placements follow the icon's moved and scaled position. Below placement keeps top-edge clamping from moving an above-icon buff card over its own icon row. Existing screen clamping remains enabled. The shared Tooltip scale, hiding and editing suppression still apply; no icon-specific position or owner is saved. A hidden icon or closed character pane clears its tooltip. Every placement derives ownership again, so switching icons or returning to a unit hover cannot retain a previous icon anchor. No content matching, item/spell lookup or extra updater is needed.

`DFRL.tools.RegisterTooltipIcon` adds the existing player buff/debuff and temporary weapon-enchant buttons while their aura layout list is built. The tooltip module discovers the existing contiguous `TargetFrameBuff`, `TargetFrameDebuff` and `TargetofTargetFrameDebuff` button series once during initialization, without repeating native slot counts. The original [target aura templates](https://github.com/MOUZU/Blizzard-WoW-Interface/blob/d162a4c0d198a4381b5b6573d975635ed7316702/1.12.1/FrameXML/TargetFrame.xml) set each hovered icon as the native owner; their builders and input scripts remain unchanged. Pooled boss/guardian debuff icons and the run bar's boss skull markers register once when created. Their existing tooltip text, snapshot timing, marker lifecycle and leave handlers remain unchanged. Registration also preserves each icon's existing OnHide handler before clearing a tooltip it owns.

The kills, gold and cache-cost fields pass their actual icon texture as an optional anchor to the same registration helper. The full counter section remains the native hover owner and hit area, while the card follows the icon within its measured and scaled content. The cache heading is **Next cache cost**, without a currency suffix, in all fourteen source/runtime catalogs; the existing displayed values are unchanged. The original visible tooltip update reapplies placement; registration adds no idle scan or updater.

Only the `tooltip` geometry/optional hidden flag in `SurvivorsDragonUiLayout` is saved, on Confirm. Cancel, world leave/logout and the existing wrapped reload path discard drafts. Both full resets restore the default position/scale and clear hiding. Unhiding never calls native Show or restores an old subject; the next native hover supplies content. Native hovers are suppressed while editing so they do not cover handles or controls.

`GameTooltip` keeps its native parent, owner and content. At the user’s request, in-world `FadeOut` calls now use native `Hide` so leaving an icon closes the card immediately, including in cursor mode. This runs the existing native hide and addon cleanup paths; it does not rebuild content or force another show.

The Lua `SetOwner` wrapper preserves the supplied owner and return, selecting `ANCHOR_NONE` while in-world to prevent subsequent content sizing from restoring an owner-relative anchor. Default-anchor hooks, OnShow and the existing visible OnUpdate reapply the chosen position and effective scale, skipping unchanged writes. A hidden edit root blocks new native shows and clears the current hover immediately. Cursor mode reuses the existing visible-tooltip updater. `DFRL.tools.PlaceHoverAtCursor` converts physical cursor coordinates and UIParent’s origin to each card’s effective scale, keeping its bottom-left corner twelve local units right and above the pointer, with existing screen clamping. Unavailable cursor or scale data falls back to normal placement. The passive layout handle remains at its saved position in both modes. No idle updater, command, asset or SavedVariable is added. Private inventory readers, comparison cards and the editor’s own hints retain their existing placement.

The inspected client also has engine-internal cursor-anchored special hovers that bypass Lua `SetOwner`. That engine cursor pass is outside these Lua anchor hooks; its exact behavior in the packaged client remains unverified. No native content is copied or rebuilt to override it.

## Equipped jewelry

Jewelry keeps its effects-only private inventory reader and all 69 compact wording templates, native values, units, conditions, `(max)` and unknown-description fallback. Its reader never owns or clears shared `GameTooltip`. The separate visible card uses `DFRL.tools.CreateHoverCard` and green DEFAULT 13 text; it has no unit metadata or health bar.

The longest natural effect line determines width, rounded up with one unit of glyph clearance and 10 units of padding per side. The text column caps at 272 units, giving a 292-unit maximum card width. Wrapped height is remeasured with native `GetHeight`; it adds 10 units of top and bottom padding. With cursor mode off, the card appears 12 units above the hovered icon. With it on, the shared cursor helper places the visible card from the existing jewelry controller’s update; no extra updater is created. The display listener reapplies its position when the preference changes, including when the cached effect text has not changed. Screen clamping, attached/detached hover, editing suppression, content measurements, private reader and cleanup remain unchanged.

## Native API adaptation

`core/tooltips.lua` provides the shared skin and registers a priority-2 module after shared Layout and before jewelry initializes. It uses stock `UI-Tooltip-Background` and `UI-Tooltip-Border` assets with a 12-unit edge, three-unit backdrop insets, fill RGBA `(0.04, 0.04, 0.08, 0.98)` and a neutral border RGB `(0.6, 0.66, 0.74)`. No texture file, source addon, framework, command or SavedVariable is added. The shared runtime manifest already includes this module.

The source DragonUI module targets Wrath. The adaptation uses the addon's legacy hook helpers, preserving existing handlers, rather than assuming Wrath's `GetUnit` and `OnTooltipSetUnit` methods. A wrapper around shared `SetUnit` preserves its native 1-or-nil return and records the explicit unit token. A post-hook restores player name color after `UnitFrame_UpdateTooltip` recolors it.

For world hovers, the inspected base client's [unit-tooltip builder](https://github.com/samwhosung/benilla/blob/f55bb79b1343629df2705d9e4207a7612a886253/crates/benilla-ui/src/script/tooltip_unit.rs#L258-L295) emits `UPDATE_MOUSEOVER_UNIT` after rebuilding the world unit tooltip. The adapter uses that event for the native `mouseover` token while the tooltip is visible and the unit exists. It does not infer a unit from its name, health values, a spell/item hover or the current target. The builder supplies no Wrath-style unit getter; source presence does not establish the packaged client's exact event ordering.

The base client’s [world hover teardown](https://github.com/samwhosung/benilla/blob/f55bb79b1343629df2705d9e4207a7612a886253/crates/benilla-app/src/ui_tooltip/mod.rs#L196-L203) clears the `mouseover` token without an empty mouseover event, and its [native fade request](https://github.com/samwhosung/benilla/blob/f55bb79b1343629df2705d9e4207a7612a886253/crates/benilla-ui/src/script/tooltip/mod.rs#L448-L467) can bypass Lua `FadeOut`. The existing visible-tooltip updater therefore hides an explicitly recorded world-unit card as soon as that token no longer exists. It does not guess the subject of other cards or add an idle updater.

Visible tooltip color maintenance is limited to the existing tooltip's five-Hz update hook, plus native show/unit events. Clearing, hiding and world leave/logout release the recorded unit and timing state; world exit hides the shared tooltip. The existing health-bar show handler is preserved before hiding that bar again. No gameplay snapshot or native unit identity is saved.

## Attribution and verification boundary

The source commit, adapted behavior and shipped MIT notice are recorded in [Tooltip-STYLE.md](../third_party/Tooltip-STYLE.md). Native Blizzard artwork remains distinct from the source project's software license. The editor's own diamond-metal artwork and appearance are unchanged.

The cursor-option and immediate-dismissal changes received source review and local formatting with the repository configuration and pinned StyLua/Prettier versions. No local tests, standalone syntax/validation checks or addon/game execution were run. GitHub Actions provides the PR static checks; its results are not awaited during delivery. Native rendering, cursor placement at different scales, hover dismissal, event ordering and profile persistence remain unverified in game.
