# Equipped jewelry

The user selected action-bar attachment design **4 — Thin shared bezel**, with the extra inner/lower curved line beneath the gold circles removed. The original bar artwork is retained, adding only five upper socket extensions. There is no jewelry panel, permanent title or side ornament. The row uses the character's five normal equipment slots: necklace, first ring, second ring, first trinket and second trinket. It is independent of the native six-pickup run build and does not add an ability row or infer run jewelry from worn gear, stats or chat.

## Data and interaction

`modules/ui/jewelry.lua` resolves `NeckSlot`, `Finger0Slot`, `Finger1Slot`, `Trinket0Slot` and `Trinket1Slot` through `GetInventorySlotInfo`, requiring five distinct valid native IDs. `GetInventoryItemTexture("player", id)` supplies each current icon. An empty or unavailable texture leaves that socket blank. No sample icons, item IDs, item names, item statistics, invented ranks or sixth slot are shipped.

Hover uses native `GameTooltip:SetInventoryItem("player", id)`, retaining the game's item description, quality and tooltip cooldown text. The row has no item-use, equip, pickup, replacement or drag handlers outside shared layout editing. Optional cooldown swipes read only native `GetInventoryItemCooldown` start/duration/enable values and use `GetTime` on the same UI clock. A generated 64-state circular shade atlas visualizes the remaining fraction without putting a square model or dark corner cover around the icon. Missing optional APIs omit those features; they do not invent gameplay timing or disable valid icons.

The base client's [inventory readers](https://github.com/samwhosung/benilla/blob/f55bb79b1343629df2705d9e4207a7612a886253/crates/benilla-ui/src/script/char_stats.rs) establish the ordinary equipped-item API and native cooldown clock, separate from the supplied AZS run tables. Source presence does not confirm the exact packaged client's live equipment publication or rendering.

Refresh is bounded to five reads per second per slot while in the world, with world-entry refresh and inventory/cooldown events scheduling the next refresh. Polling also allows native template data that arrives after an inventory event to appear. Cosmetic shade painting is bounded to 30 Hz while visible and changes UVs only when the atlas state changes. Missing required APIs or no native player hides the row and clears icons, cooldowns and owned tooltips. World leave/logout clear them immediately and stop reads/painting until world entry. No equipment or cooldown data is saved.

## Layout and original build

The five gold circles line up with action buttons **2 through 6**, one above each button. Center spacing matches button width plus its six-unit gap. The row is parented to the action bar, so its attachment follows the bar's confirmed position, uniform scale, visibility and editing draft. At the 36-unit reference button size, each visible gold circle is about 29 units wide, its outer socket is 40 units wide, and its center is 20 units above the button tops. The rim crop removes uneven transparent padding while preserving the visible size; each rim shares its icon's center anchor. The socket rail is anchored directly to the action bar, with its centers at the same positions.

`SocketRail.tga` combines all five socket arches, feet and straight spans in one continuous upper-edge texture, prepared from the existing `HDActionBar.tga`. It replaces the previous separate caps and gap pieces, which could place the feet and straight edge on different screen rows. The rail uses one bar-owned rectangle and one UV mapping; socket feet have no independent vertical anchors or scale. The original bar texture file is unchanged. Only its 12-unit upper strip switches to the rail; gaps retain the original native pixels and the lower background retains its original UV mapping. The rail uses the native bevel's color, alpha and vertical alignment at the join. Original dark bar material sits inside the border and below the bends; circular openings stay transparent. Transparent cutouts prevent the old straight edge from crossing empty socket openings. No inner/lower quarter-circle line is drawn. When jewelry is unavailable or hidden, the original complete bar background is restored.

The original 317-by-88 internal jewelry frame remains, but it is no longer an independently registered layout group. `/sdui` uses **Action bar** for the combined assembly, with its edit region extended to include the sockets. Confirm, Cancel, Hide frame, discard and full reset retain the action bar's existing lifecycle. Older standalone `jewelryBar` geometry is unused and does not move the attached row; no migration flag, new setting or SavedVariable is added. Existing action-bar geometry, other groups' geometry, native button handlers and equipment-data behavior are preserved. Editing suppresses jewelry tooltips through the action bar's shared edit callback.

The original native build HUD is hidden again at the user's request. `Native build rows` in `modules/ui/ui.lua` hides it on initialization, world entry and build-setting changes while in the world, skipping already-hidden values and guarding synchronous callbacks. This affects the native build preference only; clock, encounter and tally takeover are unchanged. Hiding the native six-pickup build does not establish a data mapping between those pickups and the five equipped items.
