# SurvivorsDragonUi

- Keep the user updated whenever meaningful progress happens.
- Never run validation, tests, syntax checks, or game startups for this project. Packaging ZIPs and publishing releases are allowed when requested, but are not addon validation.
- Public addon name and install folder: `SurvivorsDragonUi`. Keep its TOC filename, addon-loaded match and runtime texture paths consistent.
- Keep installation instructions in the README's `## Install` section. Releases copy that section with `scripts/release_notes.py`, including manual placement in `benilla-config/AddOns/` and the game's Options → AddOns → Open AddOns Folder button. Keep the public README focused on SurvivorsDragonUi without naming other addons.
- The addon is distributed alone. No companion, client patch, alternate launcher or machine-specific runtime dependency.
- Keep all appearance and placement hardcoded, with DEFAULT font and no settings UI, profiles, saved variables or frame movers. Only `/sct on|off|default` are supported configuration commands; modes are session-only. `/copy` is the user-requested utility command for opening chat diagnostics, not a configuration command.
- Integrated chat keeps the supplied visual styling and animations: fixed 520-by-340 glass-style window at bottom left (20, 40), DEFAULT font, fully transparent backgrounds (opacity 0) on the message pane, input, scroll indicator and copy-dialog fill, message fading and sliding, mouse-wheel-only history reveal, passive scroll indication and the skinned shared vanilla `ChatFrameEditBox`. All native/custom chat tabs, the Combat Log tab and the Copy button stay hidden. Open Copy exclusively with `/copy`; chat click and hyperlink handling remains native. The user's term "prettify" means formatting incoming messages, not changing this visual presentation. Only the explicitly requested level announcements, native composite stat gains, self-loot notices, class talent-experience/point notices and learned/trained ability or skill-increase notices are prettified; preserve item links, decimal values and already-collected status. Combine each level announcement with its immediately following stat gains into one chat message; retain standalone announcements when gains are absent. NPC yells use a red dynamic NPC name and colon followed by the original message, omitting the yells verb; player yells stay unchanged. Hide the requested mob approaches, lair-reclaim, battlefield-entry, refuses-to-fall, survive-the-onslaught, guardian-slain lair/strength and Swarm surrounds you announcements by generic wording, never a mob-name whitelist. Other incoming text stays unchanged. Do not enable unrelated formatting or broad filters unless requested. Keep combat damage, healing, aura and death groups out of the visible regular `ChatFrame1`; preserve regular notices such as loot, XP and reputation, native Combat Log subscriptions and channel membership. Keep native `ChatFrameN` rendering, scrolling/history and hyperlinks because the client can write directly to native frames without a Lua `AddMessage` call. Do not import Ace, profiles, movers or Wrath-only chat APIs.
- Retained faded chat is revealed only by the mouse wheel over the chat area. Hovering and input show/hide/focus do not reveal history or pause fading. New messages display normally; fading stays paused while wheel-scrolled back for reading and resumes at the bottom. The scroll indicator is passive, showing `Scroll down for latest messages` or unread status, with no clickable snap-to-bottom action.
- Register `/copy` in `modules/chat/copy.lua` through the real `_G.SLASH_SURVIVORSDRAGONUICOPY1` and `_G.SlashCmdList["SURVIVORSDRAGONUICOPY"]`, because module initialization uses DFRL's private environment. It opens a fresh `GetCaptureText()` snapshot through `ShowCopy`, independently of visible chat setup, without intercepting native chat clicks or hyperlinks.
- `modules/chat/capture.lua` is loaded before chat setup and always records session diagnostics independently of visible chat. Capture every supported `CHAT_MSG_*` event (including addon, combat and monster events), plus `UI_ERROR_MESSAGE`, `UI_INFO_MESSAGE` and `PLAYER_LEVEL_UP`, as `[EVT]` records with raw message, author and additional arguments. Capture raw Lua `AddMessage` input from every standard native chat frame as `[RAW]` before formatting, suppression or level/stat coalescing. Collapse copies of one event across frames while retaining separate identical calls on the same frame. Escape diagnostic markup pipes as the original source's `/ccdebug` did, without printing diagnostics into visible chat. History has no 512-record cap, runs while Copy is closed or open, resets on reload and has no SavedVariables, settings or new `/ccdebug` command. Opening Copy takes a snapshot; feature-detected `GetNumMessages`/`GetMessageInfo` additionally expose labeled native retained history. Do not claim access to native writes that bypass Lua and are no longer retained or exposed by the client.
- Preserve the seven-button action bar using native slots 1–6 and 12. No paging, extra bars or decorative end caps.
- Keep XP immediately below the abilities, matching the artwork width, with no numbers or hover text. Place the gold kills/gold/cache-cost bar directly underneath XP at the same width, using three equal sections with centered numbers and game icons.
- Keep a square minimap, one original-addon backpack, Character/Talents/Main Menu buttons, and original-addon health-only player/target frames filling the old health-and-resource area.
- All prettified chat messages place `+` directly against the following value or item, with no visible space: `+3% Damage`, `+9 HP`, `+420 Talent XP` and `+Item`. Apply this rule to future requested formats too. Preserve the existing policy that other incoming text, including player messages, stays unchanged except for the explicitly requested formats.
- Learned/trained abilities, spells and passive effects show only `+Name`, preserving the incoming name, intrinsic rank text and hyperlinks. Gained skills and skill increases show only `+Skill name`, without the increase counter. Match native learned/skill formats generically; never hardcode ability or class names. This is an explicitly requested formatting category; keep recipe and unlearning messages unchanged.
- Use the official 0.87.0+ API. Read phase before retained tables, native time rather than an independent clock, zone duration or native `AZS_RUN.fin`, and complete native schedules for markers. Never mutate native tables or invent missing state.
- Boss identity uses spawn `id` and `hp`/`hpm`; guardians appear only for `awake == true` or `awake == 1`. Require a received `AZS_UNITS_UPDATED` snapshot before hiding native encounter bars after reload.
- Replace only native `clock`, `bosses` and `tally` after their replacements are ready; restore captured visibility when data is unavailable or on world leave/logout.
- Client reload snapshot replay and native nameplate overlap controls remain client-side requirements. Do not substitute private snapshots or unsupported CVars.
- Preserve native V behavior and mode-aware `CombatDamage`. Independent SCT animations must survive deaths/plate reuse; show only icon and damage, with no duplicate enemy-name captions.
